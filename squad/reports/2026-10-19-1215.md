## Checklist gaps (verbatim from the risk reviewers)
### SQ-014 CHECKLIST GAPS (destructive-operations, review)
- A safety check that depends on how a Win32 API behaves over SMB or DFS (`GetFinalPathNameByHandle`, `GetFileAttributesEx`, `FindFirstFile`) needs a cited source or an Integration-tagged test. A mock that returns the "right" answer proves only the logic.
- DFS namespaces specifically: whole-tree changes on UNC paths must find the real DFS target (`NetDfsGetClientInfo`) for the root and for links inside it, and must not trust attributes read through a path the DFS client has already redirected.
- Override switches: an override must not be the suggested next step for "destination could not be determined" refusals, and one switch should not turn off unrelated guards. Otherwise false refusals teach techs to disable every guard.
- Fail-closed classifiers (allowlists): list the common real-world values that will hit the fail-closed path (APPEXECLINK in profiles, Azure File Sync tiered files, ProjFS, WCI, AF_UNIX) and decide each one explicitly, so a false refusal doesn't push people toward the override.
- Refusal text must describe what was actually found (the reparse tag or kind), not a generic "junction or symbolic link".

### SQ-014 CHECKLIST GAPS (destructive-operations, fix round 1)
- "Right target, right object" should name DFS explicitly. The DFS client hides the redirect from attributes and from GetFinalPathNameByHandle, so a DFS path has to be looked up (`NetDfsGetClientInfo`), every target has to be checked, and a lookup error has to fail closed.
- Mapped drive letters must be turned into UNC paths in the shared core, not only in the GUI. A safety check must not depend on a Win32 call that can fail with access denied, which is normal for a take-ownership job.
- Any test that calls a real P/Invoke wrapper must prove its input cannot reach the network (guard against a UNC `$TestDrive`), and new `Add-Type` signatures need a compile check under Windows PowerShell 5.1.
- A refusal's next step must fit its cause: protected folder versus a destination nobody could check versus "no link at all". Tell them apart by a shared marker constant, not by free text.

### SQ-014 CHECKLIST GAPS (destructive-operations, fix round 2)
- Redirected client drives and non-admin shares that point at a protected root: \tsclient\C (RDP drive redirection) and \server\Data where Data is shared from C:\. Both reach a Windows folder through a share name the D-036 text check does not recognise. This is pre-existing, not introduced by SQ-014.
- Native tools given a different spelling of the path than the guard checked: a drive letter versus its server path, re-resolved at run time. The checklist should require the change to act on the exact form that was checked, or a re-check immediately before the call.
- Helper functions that are always mocked: "a guard helper whose real body is never run in the gate" (here Get-DriveLetterType) should get one harmless local smoke test, so a regression in it cannot pass the gate unseen.

### SQ-015 CHECKLIST GAPS (destructive-operations)
- Advice text in a destructive tool's output, help or README that tells the tech to make a change somewhere else ("add it on the top folder", "run icacls ...") should get the same review as a write. It should state its scope (everything that inherits), name the exceptions, and give a safe command for hosts without a GUI or browser. The checklist should also have an item on removing a step: help, README, elevation and prompt texts must not still describe the removed step, and removed regression tests must still be covered for the code paths that remain (here, D-031 protected-folder handling in the GUI or core copy).
- (SQ-015 fix round 1) (1) "Prompts in non-interactive hosts fail cleanly" should also say that interactive remote consoles (Enter-PSSession, PsExec) must still be able to confirm. A detector that blocks them pushes techs to -Force and removes the confirmation. (2) Detection by pre-check must be backed by a try/catch around the prompt itself (defense in depth), with a test where Read-Host throws. (3) Advice or copy-pasteable commands the tool prints for a manual change (icacls, Set-Acl) should be reviewed like a write: scoped target, placeholder rather than a broad real path, least-privilege default, no /T. (4) Summary claims such as "none block inheritance" or "nothing found" must count the items that could not be read, rather than counting them as clean.
- (SQ-015 fix round 2) The "Prompts in non-interactive hosts fail cleanly" item should say how to detect such a host, and that a hang or an empty answer is not a clean failure:
  - `Environment.UserInteractive` is not usable: it is false in Enter-PSSession and psexec hosts where Read-Host works.
  - A Read-Host try/catch does not cover a hidden console that blocks, or stdin redirected so an empty answer is read as "no".
  - A declined or empty answer under automation should not return exit 0 if RMM treats that as success.
  - Docs should not claim scheduled tasks fail cleanly unless the claim is verified on a real task host.

### SQ-017 CHECKLIST GAPS (personal-data)
- Exports a tech saves through a dialog (not just logs, backups and fallback copies) should have a local-by-default rule. Documents and Desktop under OneDrive Known Folder Move and folder redirection should be named as non-local locations, and the existing `Test-LocalFixedPath` does not detect OneDrive because it is on a fixed disk.
- Retention and size cap for tool-private diagnostic logs (`%LOCALAPPDATA%\<Tool>\*-errors.log`) that can contain raw exception text with client paths.
- Text the user can copy by hand (selectable status or path TextBoxes in WPF GUIs) is not the ticket note, but it reaches the clipboard and ticket all the same. The checklist should say whether it must be paste-safe, or at least documented as raw.
- Client identifiers passed on relaunch or elevation command lines (`-DriveMap`, `-LogFolder` with ticket numbers) end up in 4688, Sysmon and EDR telemetry that leaves the machine.
- The formula-guard regression test should cover every client-derived column, especially file and folder names, not just one cell.

### SQ-017 CHECKLIST GAPS (destructive-operations)
- Mapped-drive or user-session data passed into an elevated process: whitelist its format, never truncate a path while parsing native tool text (`net use`), and run every guard on the resolved path.
- Relative paths given to a tool that elevates itself (cwd becomes System32): make them absolute before the relaunch.
- Single-instance mutexes in the `Global\` namespace: canonicalise the key, accept denial of service by other users (or protect with a DACL), and do not let two spellings of one log folder both get in.
- A "dry run / nothing changes" mode should list any writes that still happen at startup (log-folder probe, settings files).
- Code reloaded from the tool folder into elevated runspaces on every task, when the folder may be writable by others.
- GUI close handlers must not cancel or stop background change tasks. The close guard must run before any stop.
- Test isolation should also cover module-level paths set when a script is loaded (%LOCALAPPDATA% error logs and settings), not just paths passed in explicitly.

### SQ-017 CHECKLIST GAPS (fix round 1 re-review, personal-data)
- "Synced SharePoint/OneDrive folder" detection should name the method. Environment variables are not enough: they miss SharePoint library sync roots, and in an elevated or alternate-admin process they belong to the wrong user. The checklist should require checking the OneDrive client's registered sync roots, with a test for each.
- The CSV formula-guard item should say "a test per column that carries client-controlled text, including folder and file names", not just "a regression test". As written, a single-column test satisfies it.
- Process command lines (relaunch and elevation arguments) are not covered. Add: client data passed on a command line is limited to infrastructure identifiers (server, share, local path), never credentials or user identifiers, because 4688 command-line auditing records it.

### SQ-017 CHECKLIST GAPS (fix round 1 re-review, destructive-operations)
- Drive-letter resolution sources: when several sources map a letter to a UNC path (live CIM, a map passed from another process, remembered HKCU:\Network), the live mapping wins and stale remembered values never override it. This applies across elevation relaunches too.
- Per-session DOS devices (mapped drives and subst) do not survive UAC elevation. Every path handed to an elevated copy (script, log folder, targets) is converted or refused.
- Single-instance and lock keys use the same canonical form as the protected-path check (mapped drive vs UNC, short name vs FQDN, `\?\` forms).
- Shutdown and crash paths (Environment.Exit, pool stop, mutex release) never interrupt or unlock a committed-but-unlogged change. The close guard covers the fatal-error path as well as the window's Closing event.
- Pester mocks do not reach runspace pools or other processes. Destructive work run in the background is tested directly or through an injected write layer.
- Shared state a guard depends on (protected-root lists) must reach the background runspaces, and a missing list makes the guard fail closed.
- Validators are not canonicalisers: "valid \server\share" checks must also refuse '/' and trailing dots and spaces. Classification of admin shares (`X$`, ADMIN$, IPC$), loopback names (localhost, 127.0.0.1, ipv6-literal.net) and DFS namespace roots belongs in the "Right target" section.

### SQ-017 CHECKLIST GAPS (fix round 2 re-review, destructive-operations)
- When a target is resolved from a source that may be stale (remembered registry mappings, cached ACLs, or a map passed on from another process), the tool must say so wherever the user confirms an action or where the audit/undo log is placed, not only in a display header. This also covers deciding what an elevated relaunch runs.
- When a tool relaunches itself elevated, it must run the same script file it was started from: check by path and content, and never run a copy found through a fallback mapping.
- Path canonicalisation should also refuse `:` after the drive or share prefix (alternate data streams, for example `\\fs01\share\x:stream`). The current list stops at trailing dots and spaces.

### SQ-018 CHECKLIST GAPS (destructive-operations)
- **Add-only can still be destructive.** "Add" and "copy" are treated as safe, yet a Deny add, or a copy or add onto a drive or share root, spreads to the whole tree through inheritance. The profile should say that an inheritable ACL write on a folder counts as recursive (root guards, real location, confirm), and that adding a Deny is destructive.
- **Remote share roots are not covered.** The "high-impact roots" and "fails closed" lines do not say how to handle a remote share whose server-side folder is unknown. Add: resolve the share's local path (NetShareGetInfo or remote Win32_Share) or refuse.
- **This machine as a DFS namespace server.** Local-name classification must not skip the DFS check; DFS reparse points under a namespace root are not the data folder.
- **Interrupted-change messages.** Fatal-error and close messages must not claim "nothing was changed" once a change task has existed, and any wait-on-close must be visible.
- **Log writes reached through a wrapper.** "-WhatIf never writes a log" should state that it applies to log writes made through a wrapper in a separate runspace, not only to the change call, and should come with a test that the log folder is unchanged.
- **Removals and identifiers.** Remove choices should be explicit entries keyed by SID and type, and a no-op remove (equal before and after SDDL) is not Done.

### SQ-018 CHECKLIST GAPS (personal-data)
- Integrity checks on code relaunched or loaded from a share (`Start-Process` from UNC after elevation or STA relaunch) should cover every dot-sourced dependency, not only the entry script, because the dependency decides where client data is written.
- "Started" or intent rows written before a change: the checklist should require the README to explain how to read them, because they record client paths for changes that may not have happened.
- Retention guidance should be required to name every fallback location the tool writes to (`%LOCALAPPDATA%`, `%TEMP%`), not just the default.
- Pre-flight reads of a possibly stale remote host (hash, existence checks) should be bounded (size check, timeout), and the checklist should say that they send the tech's credentials to that host.

### SQ-018 CHECKLIST GAPS (fix round 1 re-review, destructive-operations)
- Protected-path guards must be applied to the resolved path (final path through links, long name from an 8.3 name), not only the typed or looked-up text. This holds for the high-impact roots as well as system folders, and for links inside the tree. The checklist lists canonicalisation and high-impact roots as separate bullets, which leaves room to apply only one of them.
- When a remove or revoke is matched by SID but executed by name, check sIDHistory and migrated domains specifically: a SID can translate to a name that resolves back to a different SID.
- Additive changes that spread through inheritance (Add or Copy on a drive or share root, Deny entries) belong to the same scope and confirm rules as recursive actions.
- Secondary rows written by a read-back or verification step need the same fallback when their log write fails as the primary result rows.

### SQ-018 CHECKLIST GAPS (fix round 1 re-review, personal-data)
- The "fallback to %LOCALAPPDATA%" rule should also say what happens when %LOCALAPPDATA% itself cannot be found: warn or refuse, never fall back silently to the synced or network default.
- The CSV-neutralisation test requirement should name fallback and secondary CSVs (unlogged or recovery copies) explicitly, not only the main export or log.
- The rule "warn when an explicit location is not local" should require the check to run on the fully resolved path, not the raw argument.

### SQ-018 CHECKLIST GAPS (fix round 2 re-review, destructive-operations)
- Say that a share's folder on the server must itself be checked for reparse points (a server-side junction on the share path or one of its parents), not only by text. Getting the final path from the client cannot see it.
- Every guard checked before the confirm (high-impact roots as well as D-036) must be repeated at the late point just before the irreversible native tool runs (TOCTOU), not only at lookup and count time.
- Workaround commands shown to the user for an action the tool refuses (icacls, takeown) must include the backup step and say the change won't be logged.
- An account name that can't be translated is not the same as an orphaned account (remote local accounts, unreachable domains, capability or package SIDs). Messages must not tell the admin it is deleted.
