## Checklist gaps (verbatim from the risk reviewers)
- (personal-data, SQ-019) The "Ticket notes and the clipboard" section does not say whether tenant-admin-authored names (Conditional Access policy names, sign-in-log failure reasons) count as client-controlled free text. It lists "rule names", which reads as inbox rules only. The checklist should say which side of the rule these names fall on.
- (read-only-advisory, SQ-019) Read together, the reasons in one report must not give conflicting next steps for the same account. The worst cases are a manager or plain step next to an escalation from another reason: risky user + blocked, or marker + 50057. The checklist tests each step string on its own, so cross-reason conflicts are missed.
- (read-only-advisory, SQ-019) The checklist should say explicitly that a risky or compromised user (ID Protection risk) always escalates before any unblock, re-enable or password-reset step, whatever path a plain disabled account uses (D-050).
- (read-only-advisory, SQ-019) The checklist should say that the next steps which reach the ticket note (Blocker/Probable only) must carry the escalation themselves. An escalation that lives only in a Warning or Info reason does not reach the ticket.
- (read-only-advisory, SQ-019) The verb list should add unlock, restore and "turn back on" next to take ownership.
- (destructive-operations, SQ-018) "Is this target local?" must be decided from the drive or the resolved location, not from path text. Drive letters missing from a startup-time drive map, and local symbolic links to UNC paths, must not count as local. When it cannot be determined, refuse.
- (destructive-operations, SQ-018) Account names must be resolved where they apply. For a target on another server, a name that resolves to one of this workstation's local accounts (machine SID prefix) is refused or flagged, because LookupAccountName searches local accounts before the domain.
- (destructive-operations, SQ-018) A lookup run in the background with a timeout must discard a late result and never use it for the change. Today that holds; the rule is worth pinning.
- (destructive-operations, SQ-018 re-review) "Right target, right object" should say that any decision about where a target is (this computer or a remote server), used for more than protected-path checks (for example rewriting an account name such as ".\name" to <COMPUTERNAME>\name), must follow links and mounted folders at or above the target the same way the protected-path checks do, and must fail closed when it cannot.
- (destructive-operations, SQ-018 re-review) Add an item on account names in ACL changes: a name that only resolves on this computer (a machine-local account) must not be written onto a remote object, and a "found" lookup should be done against the machine that will hold the ACL.
- (read-only-advisory, SQ-007) When a tool sits in a folder covered by more than one read-only guard (here SQ-011's AC3 for the folder and SQ-007's AC21 for the mailbox tool), say which guard covers which command families: AD/Graph, Exchange Online writes, dynamic invocation. Then each file a tool dot-sources is checked by a guard that knows that tool's write cmdlets, not just by some guard.
- (read-only-advisory, SQ-007) A test that pins a form for another guard (like AC-R2) should apply that guard's real acceptance rule, or call it. A looser copy lets a regression through until merge.
- (destructive-operations, SQ-012) The checklist has no rule for keyword matches in read-only tools. A diagnostic tool that adds a native-exe call (here `qwinsta.exe`) or a remote-registry read should be confirmed as query-only, with every write-capable API excluded. Suggested line: "A tool labelled read-only adds no write-capable call; native tools are invoked only with query verbs, and registry keys are opened non-writable."
- (destructive-operations, SQ-012) The checklist should also say that a `Remove-Item` against the `Alias:`, `Function:` or `Variable:` drives in test cleanup is not a file-system delete and passes.
- (personal-data, SQ-012) Raw command output that lists sessions or users (qwinsta, quser, `query user`, Get-BrokerSession and similar) must be reduced to the rows the verdict needs before it is stored in RawOutput or returned. A test fixture should include another user's row and assert it does not leak.
- (personal-data, SQ-012) RawOutput from one tool that is nested into another tool's result (TempProfileInvestigation wrapping the triage) counts as a "joiner" and must re-trim, not pass the whole object through.
- (personal-data, SQ-012) Registry keys known to hold secrets next to the value being diagnosed (RDInfraAgent RegistrationToken, Cloud Cache connection strings): the reader reads named values only, never enumerates the key, and has a test pinning that.
- (personal-data, SQ-012) Event log queries by ID alone, where the ID is not unique to one provider: filter on provider before anything is stored, not only before evidence is built.
- (system-configuration, SQ-012) In-process test runs: the checklist should require that tests which run a script in-process (`& script.ps1`) fake the script's own reader functions with something that outranks script-defined functions (global aliases, per the Citrix-FSLogix-Triage convention), and assert the fake was hit.
- (system-configuration, SQ-012) Advice text shown to tier 1 counts as a configuration change by proxy. Restart/reboot/service-start recommendations for multi-session hosts should carry the same logged-on-user warning the checklist requires of code that reboots, and any signed-in-user count should be framed as a point-in-time observation.
- (read-only-advisory, SQ-012) The lossy-action rule covers only "log off, reset a session". It should also cover restarting or rebooting a whole host or a service, which affects every session.
- (read-only-advisory, SQ-012) No rule covers installs, upgrades or reinstalls (.NET, agents, stacks) as next steps. They should say Escalate or name a maintenance window.
- (read-only-advisory, SQ-012) "Free up space" or "clean up" advice should count as a delete verb, and should point at a named cleanup tool or Escalate; and say whether naming a "Changes anything? Yes" tool (e.g. Cleanup-CitrixVDAStorage) counts as escalation.
- (read-only-advisory, SQ-012) Starting or enabling a service whose start type is Disabled should count as undoing a deliberate block.
- (read-only-advisory, SQ-012) The guard should state explicitly that a call by variable (`& $path`, where GetCommandName() is null) has to be resolved and allowlisted, not skipped.
- (read-only-advisory, SQ-012) Retry and fallback queries: a fallback query (for example an ID-only Get-WinEvent retry) must not turn a truncated or crowded result into a Pass.
- (personal-data, SQ-005) The ticket-note rule bans run-as admin account names only in the note. HTML/CSV reports are also attached to tickets, and those can be forwarded to clients. The checklist should say whether run-as account names are allowed in attached reports, or only in the local CSV.
- (personal-data, SQ-005) The checklist should require formula neutralisation for every string column built from client-influenced data, not only "cells taken from AD", including values from the environment or the operator (AuditedDomain, RunBy).
- (personal-data, SQ-005) The "credential never appears" test rule should require checking for the secret's actual value, not the word "password", and should list the log file and console as well as result object, CSV, HTML and note.
