## SQ-018 · FolderPermissionManager WPF app: every change (revision AC47–AC54)

This run built the revision on top of the already reviewed change buttons:

- **Deny adds.** A Deny add gets a red, non-default button and a destructive confirm that
  names the real location (AC47).
- **Copies carrying Deny entries.** A copy whose source has explicit Deny entries lists them in
  a destructive confirm (AC48). If the source's permissions aren't loaded, the confirm says they
  couldn't be checked (fail closed).
- **Roots.** Add or Copy onto a drive, share or admin-share root gets the destructive confirm
  (AC49).
- **Refused Copy targets.** Copy targets on admin shares, SYSVOL/NETLOGON, protected folders and
  high-impact roots are refused before any task starts (AC50). The check includes 8.3 names and
  junctions that lead there.
- **Typed targets that resolve elsewhere.** A typed Copy target whose real location differs from
  what was typed shows typed vs real before the change (AC51).
- **Server-side junctions.** Whole-tree changes on a remote share check every folder of the
  server-side path for junctions over the admin share. Anything unreadable refuses (AC52).
- **Late re-check.** The re-check before takeown now re-resolves the real path and applies the
  high-impact-root check, so a junction swapped in after the confirm is caught (AC53a).
- **Unknown-account advice.** It now says "check on the server first; if a name shows there,
  don't remove it", then gives a per-item backup and a remove-by-SID command (AC53b).
- **Copy dialog.** It keeps the typed list after a refusal (AC53d).
- **XAML namespaces.** They use the plain strings again, and the no-network test exempts exactly
  those two (AC54).

## Checklist gaps (verbatim from the risk reviewers)
- personal-data (SQ-018): Add an item for text that tells a person to run a command that saves client data (an `icacls /save` hint, `Export-*` instructions, and so on). Such a command should use a full path on local fixed storage that is unique per item, never a bare relative file name. The README should say what the file holds and when to delete it, in the same way the checklist already covers files the tool writes itself.
- system-configuration (SQ-018): The profile does not cover read-only P/Invoke or Add-Type reads of machine settings in tests (GetProfilesDirectoryW, NetShareGetInfo, FindFirstFileW). It lists only write cmdlets (Set-ItemProperty, Set-Service, ...). Add: "machine-state reads behind a seam (registry-backed Win32 APIs, Add-Type helpers) are mocked in every suite that reaches them, including background-pool or child-runspace function overrides."
- system-configuration (SQ-018): No item asks whether a guard that depends on reading machine state fails open or closed when the read fails (Add-Type blocked by constrained language mode or AppLocker).
- system-configuration (SQ-018): Code that reads remote servers through administrative shares (\\server\X$) during a pre-check could be flagged for Michael to verify on a real server. The server-side junction check from D-045 has only been exercised through mocks.
- read-only-advisory (SQ-018): Advice that tells a tech to remove an entry whose account "can't be looked up" must first check where the SID belongs. Machine-local SIDs of another computer cannot be translated remotely and are not orphans.
- read-only-advisory (SQ-018): Refusal next steps must not send the tech to an alternative path or route that skips the check that refused them (for example admin-share paths vs the D-045 server-side link check).
- read-only-advisory (SQ-018): Generated commands in advice (icacls, etc.) need per-item, absolute, non-overwriting backup file names, and quoting that is safe for drive-root paths.
- read-only-advisory (SQ-018): Warning and confirm text that describes Windows permission semantics (Deny vs explicit Allow, inheritance reach) is a documented Microsoft fact. It needs a Learn citation and a test, just like event IDs and status codes.
- read-only-advisory (SQ-018): The checklist is written for read-only tools. A sibling profile, or an Advice section that applies to tools that change things (FolderPermissionManager), would make this review's applicability explicit.
- read-only-advisory (SQ-018 re-review): Advice that hands a senior admin copy-paste commands which change things (icacls `/save` / `/remove` / `/restore`) should have a checklist item: the backup in that advice cannot be overwritten when the commands are run again, the restore line is shown to work for every target kind (folder, drive root, share root), and the paths are escaped for the shell they will be pasted into (cmd `%` expansion).
- read-only-advisory (SQ-018 re-review): "A failed lookup" in the fail-closed item should name short-lived causes (trust or DC outage, a foreign domain SID) as different from a deleted account before advice tells someone to remove an entry by SID.
- destructive-operations (SQ-018): A guard's "does not apply" branch (a regex that does not match, an empty normalised path, an early `return $null`) must fail closed or be proven unreachable, with a test for odd spellings such as a trailing backslash or a doubled backslash.
- destructive-operations (SQ-018): A TOCTOU re-check must re-resolve the path (final path, long path, mapped drive, server path) and apply every protected-folder rule to the result. Repeating a text-only check is not a re-check, and a test that mocks the guard to flip its answer does not prove protection.
- destructive-operations (SQ-018): The high-impact roots and protected-folder rules should cover inheritable permission adds and copies (Add, Copy), not only "recursive actions". An inheritable ACE on a root reaches the whole tree.
- destructive-operations (SQ-018): Safety rules enforced only in one UI must also be enforced in the shared core work functions, so sibling front ends (CLI, browser GUI) cannot bypass them.
- destructive-operations (SQ-018 re-review): Under "Paths are canonicalised", add: `.` and `..` segments in a typed path are refused, or resolved the way Windows resolves them (UNC `..` stops at `\\server\share`), before any server-side mapping. A guard must never normalise more aggressively than the operation does.
- destructive-operations (SQ-018 re-review): Add: an undo or restore command a tool tells a human to run is checked against the tool's real semantics, for example icacls /restore working on a directory's children. Root targets (drive root, share root) get their own test.
- destructive-operations (SQ-018 re-review): Add: every target check that reads the disk (final path, junctions) runs again just before the write, for every write path (Copy as well as take ownership), not only at lookup or confirm time.
- destructive-operations (SQ-020): When a reparse tag is added to a "treat as plain" allowlist, require the reason it cannot redirect (name-surrogate bit clear, cited), not just its MS-FSCC value.
- destructive-operations (SQ-020): Items whose owner/ACL cannot be read back (Unchecked) should not count toward a Done result. The "Results that match reality" section does not cover items that can be neither read before nor after the change.
- destructive-operations (SQ-020): The "Right target" section still says "Which reparse points count as links inside a tree waits on Q-005"; that is now decided by D-040/D-042 and should point there.
