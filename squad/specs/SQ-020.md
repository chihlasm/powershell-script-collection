# SQ-020 · Whole-tree take ownership: app-execution aliases and Azure File Sync files are plain files (D-042)

- status: ready
- size: S
- risk: high (destructive-operations profile)
- touches: `FolderPermissionManager/FolderPermissions.Core.ps1` (the D-040 allowlist `$script:RedirectFreeReparseTags`), its tests, `FolderPermissionManager/README.md`.
- depends on: SQ-014 merged to main (the allowlist lives there). Branch from main after that merge.

## Summary (plain English)
Whole-tree take ownership refuses any tree that contains a reparse point outside the known-safe list (D-040). Two common types are refused today, though they don't redirect anywhere:
- the app-execution aliases in every profile's `AppData\Local\Microsoft\WindowsApps`;
- Azure File Sync files tiered to the cloud.

Michael chose to treat both as plain files (D-042).

## Acceptance criteria
1. AC1_AllowlistHasAppExecLinkAndStorageSync: `$script:RedirectFreeReparseTags` contains `IO_REPARSE_TAG_APPEXECLINK` = 0x8000001B and `IO_REPARSE_TAG_STORAGE_SYNC` = 0x8000001E, each with a learn.microsoft.com (MS-FSCC 2.1.2.1) citation on its line or the two above. The values are verified on Learn when built.
2. AC2_PinnedTableUpdated: the existing AC20d pin tests (exact names, all values) list the two new entries (24 total). This is the only change to those tests.
3. AC3_AppExecLinkTreeIsNotRefused and AC4_StorageSyncTreeIsNotRefused: a tree containing a reparse point with each tag, whose destination is faked as `\\dc01\NETLOGON`, is not refused because of it, on both the GUI and CLI paths.
4. AC5_OtherTagsStillLinks: DFS (0x8000000A), NFS and an unknown tag are still links (regression guard).
5. AC6_ReadmeNamesThem: the README's "Allowed" paragraph names WindowsApps aliases and Azure File Sync tiered files.

## Out of scope
Any other tag. Option C (refuse links leaving the tree) stays out (D-040).
