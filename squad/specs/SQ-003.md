# SQ-003 · "Why did this user get a temporary profile?" one-user VDI verdict (plus AVD host checks)

- status: ready
- size: L as written; M after the proposed split (AVD checks move to a new item, see the end)
- risk: medium
- touches: new entry script `Invoke-TempProfileInvestigation.ps1` (placement pending Q1), Citrix
  Broker SDK lookup, file-server lock query (`Get-SmbOpenFile`), FSLogix reference table (psd1),
  SQ-001 ticket note (`CaseKit.ps1`), ServiceDesk-Toolkit START HERE row, READMEs

## Summary (plain English)
A tech types a username and the session host (or the Citrix Delivery Controller, which finds the
host). The tool checks FSLogix on that host, reads that user's FSLogix log and events, and asks
the profile file server which machine has the user's profile disk open. It returns one most
likely cause with a next step, for example "Jane has a stuck disconnected session on CTX-04
holding her profile disk. Log it off, then have her sign in again." Other possible causes are
listed with their evidence. The tool never logs anyone off and changes nothing. It writes the
SQ-001 ticket note. A separate, smaller part (proposed as its own item) adds AVD agent checks to
Citrix-FSLogix-Triage.

## What users will be able to do
- Run `.\Invoke-TempProfileInvestigation.ps1 -UserName jdoe -ComputerName CTX07`, or
  `-UserName jdoe -DeliveryController CTX-DDC01` to have Citrix find the host.
- Read the first line and know the answer: `Temporary profile check for jdoe on CTX07:
  CAUSE FOUND` (or `POSSIBLE CAUSE`, `NO CAUSE FOUND`, `CAN'T TELL`), then the cause in one
  sentence and `Next step:`.
- See below the headline, for every candidate cause, whether it was confirmed, possible, ruled
  out, or could not be checked, and why ("could not check: access denied on FS01; you need to be
  an administrator of the file server").
- See which computer holds the user's profile disk open, and the state of that Citrix session
  (active / disconnected) when a Delivery Controller was given.
- Get the SQ-001 ticket note (Checked / Ruled out / Could not check / Next step) as a text file
  and on the clipboard, with `-TicketNumber` and paste-safe behavior from SQ-001.
- Find the tool from the bundle's START HERE row for "My profile didn't load" / "temp profile",
  which now points here instead of to the two-step Triage-then-EventExport path.

## Acceptance criteria
All collectors are mocked; "jdoe", "CTX07", "CTX04", "FS01", "CTX-DDC01", `contoso` are synthetic.

Headline, ranking, verdict states
1. AC1_HeadlineIsVerdictFirst: Given mocked collectors that confirm one cause, when the script
   runs with `-UserName jdoe -ComputerName CTX07`, then the first console line is
   `Temporary profile check for jdoe on CTX07:  CAUSE FOUND`, the next non-rule line is the
   cause sentence, and a `Next step:` line follows before any evidence section.
2. AC2_LockByOtherHostIsTopCause: Given `Get-SmbOpenFile` on FS01 returns jdoe's
   `Profile_jdoe.vhdx` open from a client that resolves to CTX04, when the investigation runs
   against CTX07, then the top cause is "disk held open by another computer", the cause sentence
   names CTX04, and the evidence lists file server, share-relative file name and client computer.
3. AC3_LockHolderSessionStateFromCitrix: Given AC2 plus `-DeliveryController CTX-DDC01` and a
   mocked `Get-BrokerSession` returning jdoe Active on CTX07 and Disconnected on CTX04, then the
   cause sentence says the session on CTX04 is disconnected and the next step recommends logging
   that session off (in Citrix Director/Studio) and signing in again.
4. AC4_UnresolvedClientShownAsIp: Given the open file's client address does not reverse-resolve,
   then the lock cause is still confirmed and names the IP address, with "(name not found in DNS)".
5. AC5_TwoCausesRankedWithEvidence: Given a confirmed lock holder and a host disk under the Fail
   threshold, then the lock is the top cause and the disk cause appears under "Other possible
   causes" with its own evidence line (neither is dropped).
6. AC6_NoCauseOnlyWhenEverythingLooked: Given every check ran and none found a problem, then the
   verdict is `NO CAUSE FOUND` and the next step says to escalate with the ticket note attached.
7. AC7_CantTellWhenKeyCheckBlind: Given no cause confirmed or possible and at least one check
   could not run, then the verdict is `CAN'T TELL` (never `NO CAUSE FOUND`) and the headline's
   next step names the check that could not run and why.
8. AC8_HostUnreachable: Given the session host does not answer and CIM/registry calls throw,
   then the verdict is `CAN'T TELL`, the cause sentence says CTX07 could not be reached, and the
   exit code is 1.
9. AC9_ExitCodes: Given each verdict, the exit code without `-PassThru` is CAUSE FOUND = 2,
   POSSIBLE CAUSE or CAN'T TELL = 1, NO CAUSE FOUND = 0.

Lock-holder gate (never a false all-clear)
10. AC10_LockCheckAccessDeniedIsCouldNotCheck: Given `Get-SmbOpenFile` throws access denied, then
    the lock cause is "could not check" with the reason and the required right, and it does not
    appear under "Ruled out" anywhere (console, result object, ticket note).
11. AC11_ShareNotOnServerIsCouldNotCheck: Given VHDLocations `\\files\profiles` and
    `Get-SmbShare -Name profiles` on `files` returns nothing (for example a DFS namespace), then
    the lock cause is "could not check: the profile path may be a DFS namespace; run against the
    real file server", not "ruled out".
12. AC12_AzureLocationIsCouldNotCheck: Given CCDLocations with `type=azure` or a VHDLocations
    host ending `.file.core.windows.net`, then the lock cause is "could not check: lock holders on
    Azure Files are not checked by this version" and no SMB query is attempted against it.
13. AC13_NoOpenFileIsRuledOut: Given the share exists on FS01 and `Get-SmbOpenFile` returns no
    open VHD/VHDX for jdoe, then the lock cause is "ruled out" with "FS01 shows no open profile
    disk for jdoe".

Other causes (each rule confirmed from evidence, cited)
14. AC14_FrxsvcStopped: Given frxsvc is installed and Stopped, then "FSLogix service stopped on
    CTX07" is confirmed.
15. AC15_FrxsvcCrashed: Given a Service Control Manager "terminated unexpectedly" event for
    frxsvc in the lookback window (event ID verified on Learn), then "FSLogix service crashed" is
    confirmed with the event time.
16. AC16_LocalProfileExists: Given jdoe's FSLogix profile log contains a "Reason set to <code>"
    line whose code the reference table maps to "local profile exists", then "an existing local
    profile stopped FSLogix" is confirmed, quoting the log line and time.
17. AC17_ShareAccessDenied: Given jdoe's FSLogix log or FSLogix event shows access denied to the
    profile location, then "no permission on the profile share" is confirmed.
18. AC18_CloudCacheUnreachable: Given CCDLocations where every SMB provider is unreachable from
    the host and from this PC, then "Cloud Cache storage unreachable" is confirmed; when only some
    are unreachable it is "possible".
19. AC19_FslogixOffOrNotConfigured: Given the existing triage reports Enabled not 1 or no profile
    location, then "FSLogix profiles are off or not configured on CTX07" is confirmed.
20. AC20_HostDiskFull: Given a host disk at the triage Fail threshold, then "the server's disk is
    full" is confirmed; at Warn it is "possible".
21. AC21_UnknownFslogixCodeShownVerbatim: Given a "Reason set to 99: Something new" line whose code
    is not in the reference table, then it is shown as "Unrecognized FSLogix reason 99: Something
    new" in the evidence and does not confirm any cause.
22. AC22_TempProfileNowEvidence: Given `Win32_UserProfile` for jdoe's SID on CTX07 is loaded with
    the temporary flag (flag value verified on Learn), then an evidence line reads "jdoe is on a
    temporary profile on CTX07 right now"; when no loaded profile exists it reads "jdoe is not
    signed in to CTX07 now"; neither changes the verdict.

Citrix lookup
23. AC23_DdcPicksActiveSession: Given `-DeliveryController` and sessions Active on CTX07 and
    Disconnected on CTX04, then CTX07 is investigated, and CTX04's disconnected session is listed
    as evidence.
24. AC24_DdcNoSession: Given `Get-BrokerSession` returns nothing for jdoe, then the tool prints
    `[WARN]` "jdoe has no Citrix session the Delivery Controller knows about. Run again with
    -ComputerName <server she last used>." and exits 1 without running host checks.
25. AC25_BrokerSdkMissing: Given the Citrix Broker snap-in cannot be loaded, then the tool prints
    "Run this on a Delivery Controller or a PC with Citrix Studio, or use -ComputerName instead"
    and exits 1.

Safety, output, and contracts
26. AC26_NeverChangesAnything: Static AST check: the script calls none of `Stop-BrokerSession`,
    `Disconnect-BrokerSession`, `Close-SmbOpenFile`, `Invoke-CimMethod`, `Invoke-WmiMethod`,
    `logoff`, `rwinsta`, `reset`, `Stop-*`, `Restart-*`, `Set-*` (except `Set-Content` for its own
    output and SQ-001's clipboard helper), `Remove-*`, `New-ItemProperty`.
27. AC27_TicketNoteRespectsGate: Given AC10's blind lock check and a ruled-out frxsvc check, when
    run with `-TicketNumber 482113 -OutputPath $TestDrive`, then the SQ-001 note lists the lock
    check under "Could not check" and frxsvc under "Ruled out", and the Next step equals the
    console's next step.
28. AC28_PasteSafeDropsPaths: Given the SQ-001 paste-safe mode, then the note contains no VHD(X)
    path, profile path, UNC path or IP address; the server and user names remain.
29. AC29_PassThruShape: Given `-PassThru -Quiet`, then the object has `CheckId`
    (`fslogix.tempprofile`), `Status`, `Verdict`, `Summary`, `Causes` (each with `Id`, `Title`,
    `State` in Confirmed/Possible/RuledOut/CouldNotCheck, `Evidence`, `NextStep`, `Rank`),
    `Evidence`, `RecommendedNextSteps`, `RawOutput`, `StartedAt`, `FinishedAt`, `Error`.
30. AC30_ReferenceTableCitedAndInParity: Every code in the FSLogix reference psd1 has a
    learn.microsoft.com URL, and the script's built-in fallback table equals the psd1 (pattern of
    `AD-LockoutDiagnostics/Tests/SharedReferenceParity.Tests.ps1`).
31. AC31_Ps3Floor: The new script declares `#Requires -Version 3.0`, parses with no errors, and
    passes the same checks as `Citrix-FSLogix-Triage/Tests/Compatibility.Tests.ps1` (no classes,
    `::new()`, `.Where()/.ForEach()`, 5.x-only cmdlets including `Import-PowerShellDataFile`
    unguarded, `-NoNewline`, `-Depth`).
32. AC32_BundleRowReplaced: The ServiceDesk-Toolkit START HERE table has exactly one row for the
    temporary-profile symptom, and it names `Invoke-TempProfileInvestigation`; no new row is added.

## Out of scope
- Logging off, resetting or disconnecting any session, closing open files, deleting local
  profiles, repairing VHDX. The tool recommends; it never acts.
- RDS and AVD session discovery (only `-ComputerName` or the Citrix lookup in v1).
- Lock holders on Azure Files (needs Az; reported as "could not check").
- DFS namespace resolution to the real file server (reported as "could not check" with a hint).
- ODFC (Office container) causes; only the profile container.
- FSLogix include/exclude group membership as a cause (possible follow-up).
- Multi-user or farm-wide scans (Citrix-FSLogix-HealthCollector does that).
- The AVD agent checks (proposed split: SQ-012 below).

## Approach
- **Placement (pending Q1, recommended):** a second entry script
  `Citrix-FSLogix-Triage/Invoke-TempProfileInvestigation.ps1` beside
  `Invoke-CitrixFSLogixTriage.ps1`. It dot-sources the triage with `-LoadFunctionsOnly` (companion
  in the same folder, the `Resolve-CompanionScript` pattern in
  `AD-LockoutDiagnostics/Invoke-ADLockoutInvestigation.ps1:266`) and calls
  `Invoke-CitrixFSLogixTriage` for host evidence (services, Enabled, locations, events, disk,
  share reach). No triage logic is copied. The folder already ships in the bundle manifest
  (`ServiceDesk-Toolkit/Build-ServiceDeskToolkit.ps1:73`) and gets SQ-001's `CaseKit.ps1` in
  SQ-001's first slice.
- **New collectors in the new script** (each in its own try/catch returning a three-state result,
  as in `Get-DriveMapVerdict`, `DriveMap-Diagnostics/Invoke-DriveMapInvestigation.ps1:584`):
  - User SID: `[System.Security.Principal.NTAccount]` `.Translate()`; no AD module needed.
  - FSLogix profile log for the user: read `Profile-*.log` for the lookback window from the
    host's log folder (default `C:\ProgramData\FSLogix\Logs\Profile`, or the documented logging
    directory setting if present; verify on Learn) via `Invoke-Command` with `Test-Path` /
    StreamReader (UTF-16LE with BOM, as in `Parse-FSLogixLogs/Parse-FSLogixLogs.ps1:157`). Copy
    only the regexes needed (`LoadProfile`, `Status set to`, `Reason set to`, `[ERROR:code]`),
    restricted to the user's session block. Do not call Parse-FSLogixLogs (other folder).
  - Service crash events: System log, Service Control Manager, frxsvc (IDs verified on Learn).
  - `Win32_UserProfile` for the SID on the host (temporary flag; evidence only).
  - Lock holder: derive file server(s) from VHDLocations / SMB CCDLocations (host part of the
    UNC). `Import-Module SmbShare` in try/catch; `New-CimSession` to the file server;
    gate with `Get-SmbShare -CimSession -Name <share>`; then `Get-SmbOpenFile -CimSession
    -ClientUserName <DOMAIN\user>` filtered to `*.vhd` / `*.vhdx`, with a path fallback match on
    the SID folder (`<SID>_<user>` or FlipFlop `<user>_<SID>`). Reverse-resolve
    `ClientComputerName` with `[System.Net.Dns]::GetHostEntry` in try/catch.
  - Citrix lookup (`-DeliveryController`): copy `Import-CitrixBrokerSdk` from
    `Citrix-FSLogix-HealthCollector/Get-CitrixFSLogixHealth.ps1:540`; `Get-BrokerSession
    -AdminAddress <DDC> -UserName <DOMAIN\user>` (verify parameter names on Citrix developer
    docs, as `Get-CitrixFSLogixHealth.ps1:611` does).
- **Ranker** `Get-TempProfileVerdict` (pure function, no I/O): evaluates every rule, never
  short-circuits, never returns empty. Fixed rank order (squad decision, see below): 1 disk held
  by another computer/session, 2 frxsvc stopped or crashed, 3 FSLogix off or not configured,
  4 no permission on the profile share, 5 Cloud Cache unreachable / profile share unreachable,
  6 existing local profile, 7 server disk full. Top cause = highest-ranked Confirmed; else
  highest-ranked Possible; else NO CAUSE FOUND only if no rule is CouldNotCheck; else CAN'T TELL.
- **Reference data:** `Citrix-FSLogix-Triage/FSLogixReference.psd1` with FSLogix status/reason/
  error codes used by the rules, each with a Learn URL; loaded with the 3.0-safe
  `Import-PowerShellDataFile` / `Import-LocalizedData` fallback from
  `AD-LockoutDiagnostics/Export-ADAuthSourceEvidence.ps1:287`; built-in fallback table in the
  script guarded by a parity test.
- **Output:** console verdict first, then "Other possible causes", "Ruled out", "Could not
  check", then evidence. `-OutputPath` writes `TempProfile_<user>_<host>_<yyyy-MM-dd_HHmmss>.txt`
  and `.csv` (pattern of `Export-TriageReport`). SQ-001's note via `CaseKit.ps1`
  (`New-TicketNote`), `-TicketNumber`. `[PASS]/[WARN]/[FAIL]/[INFO]` colours.
- **Params:** `-UserName` (mandatory; `jdoe` or `CONTOSO\jdoe`; bare names get
  `$env:USERDOMAIN`), `-ComputerName` / `-DeliveryController` (parameter sets, one required),
  `-EventLookbackHours` (1-168, default 24), `-OutputPath`, `-TicketNumber`, `-PassThru`,
  `-Quiet`, `-LoadFunctionsOnly`. Aliases `-AffectedUser`/`-AffectedDevice` as in the triage.
- **Docs:** full comment help with REFERENCES; `Citrix-FSLogix-Triage/README.md` section;
  root `README.md` index line; `ServiceDesk-Toolkit/README.md` row 22 rewritten to point here
  (the Triage stays linked in its section as the host-only check).
- **Microsoft facts to verify on Learn before coding and cite in code** (CLAUDE.md; the Learn
  MCP was not available to this planner, so none of these are confirmed yet): `Get-SmbOpenFile`
  parameters and `ClientUserName` format and minimum OS; `Get-SmbShare -CimSession`; Service
  Control Manager event IDs for an unexpected service stop; `Win32_UserProfile` temporary flag;
  FSLogix log location and logging-directory setting; FSLogix status/reason codes (including
  "local profile exists") and the event 26 known issue
  (https://learn.microsoft.com/fslogix/troubleshooting-known-issues); `DeleteLocalProfileWhenVHDShouldApply`
  (https://learn.microsoft.com/fslogix/reference-configuration-settings). Any fact with no Learn
  page is marked NOT VERIFIED ON LEARN in `.NOTES`, as the triage does for disk thresholds.

### Assumed by the squad
- Depends on SQ-001 and is built after it: the ticket note, `-TicketNumber`, paste-safe mode and
  the "Ruled out only when the gate could look" rule come from SQ-001's `CaseKit.ps1`, which
  SQ-001 already copies into Citrix-FSLogix-Triage. If SQ-001's function names differ from those
  used here, SQ-001's spec wins. (Evidence: BACKLOG SQ-001 first slice; I-03 card.)
- Reuse the triage by dot-sourcing it rather than copying its checks. Reason: same-folder
  companion is the established pattern and avoids a fourth copy of the FSLogix checks.
- Fixed rank order listed in Approach. Reason: causes with user-specific, direct evidence (a lock
  held elsewhere, a crashed service) outrank host conditions that may be incidental; every other
  cause is still shown with evidence, so a wrong top pick is visible. Reversible.
- The FSLogix text log is read directly (copied regexes), not through Parse-FSLogixLogs. Reason:
  that script is in another folder, has no `-LoadFunctionsOnly`, and is not in the bundle.
- Lock check is gated by `Get-SmbShare` on the derived server. Reason: a DFS namespace or wrong
  server would otherwise return "no open files", a false all-clear (P-001).
- Bare user names take `$env:USERDOMAIN`. Reason: matches how techs type names; the SID
  translation fails loudly if wrong.
- Script name `Invoke-TempProfileInvestigation.ps1`. Reason: matches `Invoke-ADLockoutInvestigation`
  and `Invoke-DriveMapInvestigation`.
- Exit codes follow the triage (0 / 1 / 2). Reason: consistency for callers.
- The idea card says Citrix-FSLogix-Triage "already has an AVD deployment mode"; it does not
  (grep finds AVD only in its help text). AVD detection is new work in the split item.

## Risk and safety notes
- personal-data: output holds user names, SIDs, host names, file-server paths and client IPs.
  Collect only those. Encode all values in any HTML. If the default output location is inside the
  repo folder, add a `.gitignore` pattern (`**/TempProfile_*`) in the same change. Paste-safe note
  drops paths and IPs (AC28). Tests use synthetic data only.
- Read-only: no session, file-handle, profile, registry or service change (AC26). Recommending a
  logoff is text only.
- Not system-configuration or destructive-operations: no keywords from those profiles are used.
- Confident-wrong-answer risk: handled by the three-state rules, the lock gate (AC10-AC12), and
  showing every cause's evidence (AC5).
- Rights: the tech needs local admin on the session host and on the file server for the lock
  check; without file-server rights the main feature reports "could not check".

## Proposed split: SQ-012 · AVD host checks in Citrix-FSLogix-Triage (draft)
Size S, risk low, P2 suggested (Q2). Adds to `Invoke-CitrixFSLogixTriage.ps1` an AVD check set
that runs only when the host is detected as AVD (RDAgentBootLoader service present or
`HKLM\SOFTWARE\Microsoft\RDInfraAgent` exists); on Citrix/RDS hosts it adds nothing. Every fact
below must be verified on https://learn.microsoft.com/troubleshoot/azure/virtual-desktop/troubleshoot-agent
and https://learn.microsoft.com/azure/virtual-desktop/troubleshoot-statuses-checks and each
finding's Action carries the Learn fix URL. Draft ACs (become AC1.. in that spec):
- AVD-AC1: not AVD, no AVD evidence items added and existing tests unchanged.
- AVD-AC2: RDAgentBootLoader not running = Fail with the Learn link.
- AVD-AC3: `IsRegistered` not 1 = Fail ("host is not registered to its host pool").
- AVD-AC4: Application event 3277 containing INVALID_REGISTRATION_TOKEN, EXPIRED_MACHINE_TOKEN,
  INVALID_FORM, ENDPOINT_NOT_FOUND or InstallMsiException = Fail naming the error and its fix.
- AVD-AC5: events 3703, 3019, 3389 each mapped to their documented meaning and fix.
- AVD-AC6: `rdp-sxs` listener not in Listen state = Fail; unparseable `qwinsta /server:` output
  (for example a localized state word) = Warn "could not check", never Pass.
- AVD-AC7: registry/service/event read failure = Warn, never Pass (existing triage rule).
- AVD-AC8: still PS 3.0 compatible and pure ASCII (existing Compatibility tests).
