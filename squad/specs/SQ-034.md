## Summary (plain English)
The DNS Record Audit Tool is a web page served by a small local web server inside the script;
it has no window of its own. This item gives it the same "smoke test" start the Folder
Permission Manager got in SQ-029: the real script starts its real local web server on a free
port, fetches its own page and its first data call from itself, then shuts down and prints PASS
or FAIL. It opens no browser, loads no DNS or AD modules, contacts no domain controller or DNS
server, and writes no file. The smoke runner then checks this tool as well as the Folder
Permission Manager.

## What users will be able to do
- Michael (or the squad gate, once `smokeCommand` is set) runs
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tests\Invoke-SmokeTest.ps1` and, besides
  the Folder Permission Manager line, gets
  `[PASS] Search-DNSRecords-GUI.ps1: ...` within about 5-15 seconds, or a `[FAIL]` line saying what
  went wrong (the web server could not start, the page was not served within 30 seconds, a data
  or export request arrived during the smoke test), with a non-zero exit code.
- A tech can run `.\Search-DNSRecords-GUI.ps1 -SmokeTest` on a workstation or server to check a
  copy of the tool starts there, without a browser opening, without RSAT, and without leaving
  files behind.
- The runner refuses a target that does not declare `-SmokeTest` instead of starting it normally.
- Normal starts of the tool are unchanged (modules, port 8080, browser, exports).

### What "window rendered off-screen" means for this tool
Search-DNSRecords has no WPF window: its UI is HTML served by an `HttpListener` on
`http://localhost:<port>/` and shown in the user's browser. The smoke equivalent of "the window
rendered off-screen" is: the real listener starts, the real request loop and `Invoke-Route` serve
`GET /` (the full page) and `GET /api/status` (the page's first data call, made by `initApp()`), and
an in-script client fetches both over loopback and checks their content. No browser is launched,
so nothing appears on screen; under the runner the console is hidden too (`CreateNoWindow`).
"Closed on a timer" is the deadline tick inside the request loop's existing 100 ms wait.

## Approach
**Reference implementation.** SQ-029 (`squad/specs/SQ-029.md`,
`FolderPermissionManager/FolderPermissionManager-GUI.ps1` `#region Smoke test`): same helper names
and shapes where they fit (`Get-SmokeVerdict`, `Get-SmokeTickAction`, `Add-SmokeFailure`,
`$script:SmokeFailures` as a `List[string]`, `$script:SmokeState`), same exit codes (app 0/1;
runner 0/1/2), same 30 s app deadline / 90 s runner / 120 s gate layering.

**App changes (`Search-DNSRecords-GUI.ps1`).**
- Param block: add `[switch]$SmokeTest` and `[switch]$LoadFunctionsOnly`. Help: `.PARAMETER` for
  both, an `.EXAMPLE` with `-SmokeTest`, `.NOTES` "Files written" and REFERENCES (see below).
- First statement after the param block: `$script:SmokeMode = $SmokeTest.IsPresent` (the
  "pre-flag startup paths" checklist gap: everything that does work comes after it; the
  `$OutputPath = (Get-Location).Path` default only reads the current location).
- Move the module-loading block into `Import-ToolModules` (returns `$true`/`$false`; same lines,
  same `[FAIL]`/`[WARN]`/`[INFO]` texts) so `-LoadFunctionsOnly` and tests can skip it. The
  `$baseUrl` line moves into the startup region (it depends on the chosen port).
- New seams, each the only place its API appears (AC2): `Get-FreeLoopbackPort` (a
  `TcpListener` on `IPAddress.Loopback` port 0, read `LocalEndpoint.Port`, stop),
  `New-ToolListener -Prefix` (create, add prefix, `Start()`), `Open-ToolBrowser -Url`
  (`Start-Process`), `New-SmokeProbeClient` (`System.Net.WebClient`, `Proxy = $null`, UTF-8).
- New `#region Smoke test` among the function definitions: `Get-SmokeDeadlineSeconds` (30),
  `Add-SmokeFailure` (writes the `[FAIL]` line once, dedupes identical text: SQ-029 review
  finding), `Test-SmokeRefusal -Route`, `Send-SmokeRefusal -Response` (status 403, JSON
  `{ error = 'Not available during the smoke test.' }`), `Test-SmokePageBody`,
  `Test-SmokeStatusBody`, `Start-SmokeProbe -BaseUrl` (two clients, `DownloadStringTaskAsync` for
  `/` and `/api/status`, a stopwatch), `Update-SmokeState -Probe` (reads task state without
  blocking, runs the body checks, records times and errors), `Get-SmokeTickAction`,
  `Get-SmokeVerdict`, `$script:SmokeState`. ASCII only.
- Guard at the top of the six handlers that reach the network or disk (`Get-DnsZones`,
  `Invoke-DnsSearch`, `Invoke-StaleDetection`, `Invoke-DcCompare`, `Invoke-ExportCsv`,
  `Invoke-ExportHtml`): `if (Test-SmokeRefusal -Route '<METHOD /path>') { Send-SmokeRefusal
  $Response; return }`. This is the "enforce no-write at the chokepoint" checklist gap: the
  guard sits in the functions that call `Get-DnsServer*`, `Get-ADComputer`, `Export-Csv` and
  `WriteAllText`, not only in the dispatcher, so any local process that hits the smoke port
  cannot make it read DNS/AD or write a file. `Invoke-Route`, `Send-Html`, `Get-Status`,
  `/api/shutdown` and 404 stay as they are.
- `if ($LoadFunctionsOnly) { return }` after `$script:htmlContent` and before a new
  `#region Startup`.
- Startup region. Normal path keeps today's order and texts: `Import-ToolModules` (return if
  `$false`), `$baseUrl` from `$Port`, `New-ToolListener` (catch: existing `Write-Error` + `exit 1`),
  `Open-ToolBrowser` unless `-NoBrowserOpen`, request loop, `finally` stop/close. Smoke path:
  1. `-OutputPath` bound -> `[FAIL]` + `exit 1` (AC7);
  2. no `Import-ToolModules`; module flags stay `$false`; one `[INFO]` line saying modules are not
     loaded in the smoke test;
  3. port = `-Port` if bound, else `Get-FreeLoopbackPort`; `$baseUrl = "http://localhost:$port/"`;
  4. `New-ToolListener`; on error `Add-SmokeFailure` and fall through to the verdict (`exit 1`),
     never `Write-Error`;
  5. never `Open-ToolBrowser` (`-NoBrowserOpen` implied);
  6. `Start-SmokeProbe -BaseUrl $baseUrl` after the listener started, before the loop;
  7. in the loop's existing `while (-not $contextTask.IsCompleted)` wait, on each 100 ms pass:
     `Update-SmokeState`, `Get-SmokeTickAction`; `Close`/`TimedOut` -> leave both loops (set
     `$script:running = $false` and `break`); a completed context is still routed through
     `Invoke-Route` as normal (that is how the probe's requests are served);
  8. after `finally` (listener stopped and closed): write `Get-SmokeVerdict` lines and
     `exit` its ExitCode. Under `-File` that is the process exit code; no `Environment.Exit`
     needed (no WPF).
- The client must use the same `localhost` host name as the prefix: http.sys matches the Host
  header, so `127.0.0.1` would get 400.

**Runner changes (`Tests/Invoke-SmokeTest.ps1`).**
- Add `'Search-DNSRecords\Search-DNSRecords-GUI.ps1'` to `$script:DefaultTargets` (D-061).

## Test plan
- Pester 5 under pwsh, new suite `Search-DNSRecords/Tests/Search-DNSRecords-SmokeTest.Tests.ps1`
  with AC1-AC21 in unit `Describe` blocks and AC22-AC23 in a `Describe` tagged `Integration`.
  Plus the fixture updates to `Tests/Invoke-SmokeTest.Tests.ps1` (AC21, AC22, AC23 there).
- Loading: `. $AppPath -LoadFunctionsOnly` inside `BeforeAll` (the script sets
  `$ErrorActionPreference = 'Continue'` at the top; tests that care set their own). Handlers with
  `HttpListener*` parameter types are redefined from their AST text with the types replaced by
  `[object]` (FolderPermissionManager Handlers suite pattern).
- Stand-ins: fake listener `[PSCustomObject]` with `Start`/`Stop`/`Close`/`GetContextAsync`
  script methods (never-completing task from a `TaskCompletionSource[object]`, or
  `Task.FromResult`); fake contexts with `Request.Url.AbsolutePath`, `Request.HttpMethod`,
  `Request.QueryString`, and a `Response` whose `OutputStream` is a `MemoryStream`.
- Backstops in every in-process run (AC4-AC9, AC17, AC18): `Start-Process`, `Open-ToolBrowser`,
  `Import-ToolModules` (except AC17/AC18), real-named throwing stubs of `Get-DnsServerZone`,
  `Get-DnsServerResourceRecord`, `Get-ADComputer`; `New-ToolListener` always faked, so no real
  listener; `$env:ADPS_LoadDefaultDrive = '0'` for the suite. Each throwing fake is also asserted
  with `Should -Invoke -Times 0 -Exactly`. Fake storage in mocks uses `$global:` with cleanup by
  name (SQ-029 build note: in a mock called from an `& $Path` run, `$script:` is the run's scope).
- In-process runs use `exit`, which ends only the script and sets `$LASTEXITCODE`.
- Repo gates: `Tests\Test-ScriptParse.ps1` (5.1 parse; the script already holds non-ASCII text, so
  it must keep its UTF-8 BOM, `Tests\ScriptEncoding.Tests.ps1`), `Tests\PSVersionFloor.Tests.ps1`
  (script stays `#Requires -Version 5.1`).
- Edge cases: busy port, explicit `-Port`, `-OutputPath` refused, deadline, a faulted probe task,

## Decisions
### Confirmed by the owner
- D-061: one smoke-mode item per GUI after SQ-029; the runner takes a list of GUIs, each added in
  one line. This is the Search-DNSRecords one.
- D-062: guard rule on the runner when `smokeCommand` is set (not part of this item's code).
- 2026-11-11 plan: depends on SQ-031, which owns the shared runner changes (see Revision notes). Squad call: smoke proof is server-only (listener serves / and /api/status to an in-script client; no browser), same as SQ-036.

### Assumed by the squad
- "Window rendered off-screen" for a browser GUI = the real listener served the page and the
  status call to an in-script loopback client, with no browser launched. Reason: the tool has no
  window; launching a browser would show something on screen and depend on the default browser.
- The smoke loads neither the DnsServer nor the ActiveDirectory module. Reason: the gate machine
  may not have RSAT DNS (the smoke would fail for reasons unrelated to the code), and importing
  ActiveDirectory mounts the `AD:` drive, which contacts a domain controller (SQUAD.md "Real
  systems"). The status call reports both modules as not loaded, which the body check accepts.
- Free loopback port unless `-Port` is given. Reason: a fixed 8080 would fail when a real copy of
  the tool is open, and would block that copy while the smoke runs.
- `-SmokeTest -OutputPath` is refused; `-NoBrowserOpen`, `-Port`, `-StaleThresholdDays` are
  accepted. Reason: same rule as SQ-029's `-LogFolder`/`-DriveMap` refusal (parameters that point
  at real folders are refused); the others are harmless.
- Data and export routes are refused inside each handler and count as smoke failures. Reason:
  destructive-operations checklist "enforce at the chokepoint"; a request reaching them during a
  smoke means something unexpected is talking to the port.
- No elevation, mutex, log or settings logic is added or skipped: the tool has none. Reason: the
  script has no `Request-Elevation`, mutex, log file or settings file (read in full); AC2's AST
  check and AC5's file check pin that the smoke still writes nothing.
- The declare check and count-agnostic runner tests land in this item if `main` does not have
  them yet. Reason: SQ-029 review flagged the check as mattering for SQ-031..SQ-036, and this item
  cannot add its target without updating AC21/AC22's counts anyway.
- No real `HttpListener` in unit tests; the real one runs only in the Integration tests. Reason:
  repo convention (`FolderPermissionManager-App.Tests.ps1` header: "No network, no HttpListener").
- The probe uses `System.Net.WebClient` with `Proxy = $null`. Reason: available in .NET Framework
  4.5+ and .NET 8 without `Add-Type`; a null proxy avoids reading the system proxy and WPAD
  discovery (a network read).
- REWRITE: no. The tool's behaviour is unchanged; module loading moves into a function without
  changing its text.

## Risk and safety notes
- No risk profile path matches `Search-DNSRecords/**`. The tool contains `Export-Csv` (a
  personal-data keyword); this item adds no export and refuses exports during the smoke (AC10).
  `Tests/Invoke-SmokeTest.ps1` starts processes: only through `Start-SmokeProcess`, now only for
  targets that declare `-SmokeTest` (AC20), and the unit tests never start one.
- destructive-operations "Elevation, prompts and shutdown": the smoke is a "nothing changes"
  mode; its help lists the startup writes, which are none (AC1, AC5).
- SQUAD.md "Real systems": the smoke contacts no DC, DNS server or network beyond loopback
  (AC5, AC10, AC16). Agents do not run the runner or the Integration tests (D-062, run rules).
- The smoke listener is reachable by any local process for a few seconds; it serves only the
  page and the status JSON and refuses everything that reads DNS/AD or writes (AC10).
