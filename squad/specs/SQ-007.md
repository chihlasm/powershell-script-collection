# SQ-007 · Mailbox check: the facts, with "do NOT reset yet" on takeover signs

- status: ready
- size: M (L if Q1 = A without a split)
- risk: medium
- touches: the SQ-002 folder (new entry script + new mailbox core file), SQ-001 CaseKit ticket
  note (consumer only), `ServiceDesk-Toolkit` README/bundle row, root `README.md`, `.gitignore`

## Summary (plain English)
A tech enters one mailbox and gets one read-only report with the facts they would otherwise
click through the Exchange admin center for: who can open it or send as it, where its mail is
forwarded, its inbox rules (including hidden ones), size, archive, holds, whether it is shared,
and a recent message trace. If anything looks like an account takeover, the first line says
"Possible account takeover: do NOT reset the password or delete the rule yet. Escalate." and
the next step is CIPP's BEC report. If a section could not be read, the tool says "partly
checked" and never gives an all-clear.

## What users will be able to do
- Run `.\Get-M365MailboxCheck.ps1 -Identity accounts@contoso.com` from the SQ-002 folder on a
  tech workstation. On connecting, a banner shows the tenant and the signed-in account before
  any mailbox is read, so a wrong-tenant run can be stopped with Ctrl+C.
- See a verdict block first, in one of three forms:
  - **Takeover signs found:** `Possible account takeover: do NOT reset the password or delete
    the rule yet. Escalate.`, then each sign in plain English (for example "Mail is forwarded
    to an outside address at gmail.com", or "Inbox rule 'xx' moves mail to RSS Feeds and marks
    it read"), then `Next step: Check CIPP's BEC report for this user.`
  - **Partly checked:** `PARTLY CHECKED - no takeover signs in what could be read, but these
    could not be checked: <sections and why>.` with the fix (for example the Exchange role
    needed).
  - **All checked, nothing suspicious:** `No takeover signs found in the checks below.` This
    wording appears only when every sign-producing section was read successfully.
- Below the verdict, read the facts: Full Access, Send As, Send on Behalf; mailbox forwarding;
  every inbox rule (hidden ones marked); size against quota; archive on/off and size; holds
  (litigation, in-place/retention); mailbox type (user, shared, room, equipment); and the
  recent message trace (sent and received, last 7 days by default).
- Get an HTML report and CSVs under `-OutputPath`, and (with SQ-001) a paste-safe ticket note
  in the four-part format, written to file and clipboard, honouring `-TicketNumber`.
- There are no switches that change anything. Nothing is ever deleted, disabled or reset.

## Acceptance criteria
Each maps to one Pester test named `AC<n>_...`. All Exchange cmdlets are mocked.

1. AC1: Given a connected Exchange session for tenant `contoso.onmicrosoft.com` as
   `admin@contoso.onmicrosoft.com`, when the check runs, then a banner naming that tenant and
   account is written before the first mailbox cmdlet (`Get-EXOMailbox`) is called.
2. AC2: Given `-Identity` that matches no mailbox, when the check runs, then it prints
   `[FAIL] No mailbox found for '<identity>' in tenant <tenant>.`, writes no verdict or
   report, and exits with code 3.
3. AC3: Given mailbox permissions containing `NT AUTHORITY\SELF`, an inherited entry, a Deny
   entry and an explicit FullAccess grant to `jdoe@contoso.com`, when Full Access is
   collected, then only `jdoe@contoso.com` is listed.
4. AC4: Given recipient permissions with `NT AUTHORITY\SELF` and a SendAs grant to
   `jdoe@contoso.com`, when Send As is collected, then only `jdoe@contoso.com` is listed.
5. AC5: Given `GrantSendOnBehalfTo` holding one recipient, when Send on Behalf is collected,
   then that recipient is listed; given it empty, then the section reads "Nobody".
6. AC6: Given `ForwardingSmtpAddress = smtp:x@gmail.com` and accepted domains `contoso.com`
   only, when signs are evaluated, then an `ExternalForwarding` sign is raised naming
   `gmail.com` and whether a copy is kept (`DeliverToMailboxAndForward`).
7. AC7: Given mailbox forwarding to an address in an accepted domain, when signs are
   evaluated, then forwarding is shown as a fact and no takeover sign is raised.
8. AC8: Given an inbox rule with `ForwardTo`, `ForwardAsAttachmentTo` or `RedirectTo` an
   address outside the accepted domains, when signs are evaluated, then an
   `ExternalRuleForward` sign is raised for that rule (one test, cases for each property).
9. AC9: Given an inbox rule with `DeleteMessage` or `SoftDeleteMessage` set, when signs are
   evaluated, then a `RuleDeletesMail` sign is raised.
10. AC10: Given an inbox rule that moves mail to RSS Feeds, RSS Subscriptions, Conversation
    History, Deleted Items, Junk Email or Archive, or that moves mail and marks it read, when
    signs are evaluated, then a `RuleHidesMail` sign is raised; a rule that only moves mail
    to an ordinary user folder raises none.
11. AC11: Given the check runs, then `Get-InboxRule` is called with `-IncludeHidden`; given
    the hidden built-in junk-mail rule plus one other hidden rule, then only the other rule
    raises a `HiddenRule` sign and both appear in the rule list marked hidden.
12. AC12: Given mailbox and statistics fixtures, when facts are built, then the report shows
    mailbox type, total size, prohibit-send quota, archive enabled and its size, litigation
    hold, and any in-place/retention holds, with "not available" for a missing value rather
    than 0 or blank.
13. AC13: Given `-TraceDays 7`, when the trace runs, then `Get-MessageTraceV2` is called
    twice (once by `-SenderAddress`, once by `-RecipientAddress`) with a window of 7 days
    ending now and the documented maximum result size; `-TraceDays 11` is rejected by
    parameter validation.
14. AC14: Given a trace query that returns the maximum result count, when the report is
    built, then the trace section carries a `[WARN]` "results were cut off at <n>; rerun
    with a smaller -TraceDays".
15. AC15: Given at least one takeover sign, when the verdict is built, then line 1 is exactly
    `Possible account takeover: do NOT reset the password or delete the rule yet. Escalate.`,
    each sign follows, the next step is exactly `Check CIPP's BEC report for this user.`, and
    the exit code is 1.
16. AC16: Given `Get-InboxRule` throws an access-denied error and no other section raises a
    sign, when the verdict is built, then it starts with `PARTLY CHECKED`, names "Inbox rules"
    and the reason under could-not-check, does not contain `No takeover signs found`, and the
    exit code is 2.
17. AC17: Given every sign-producing section succeeds and none raises a sign, when the verdict
    is built, then it reads `No takeover signs found in the checks below.` and the exit code
    is 0.
18. AC18: Given an external-forwarding sign and a failed message trace, when the verdict is
    built, then the takeover line is still first and the trace appears under could-not-check.
19. AC19: Given rules with conditions containing keywords (`invoice`) and external forwarding
    to `x@gmail.com`, when the SQ-001 ticket note is produced, then the note contains the
    sign kinds and `gmail.com` but not `invoice`, not `x@gmail.com`, and no trace rows; and a
    section that failed is listed under "Could not check", never "Ruled out".
20. AC20: Given a rule named `<script>alert(1)</script>`, when the HTML report is written to
    `$TestDrive`, then the name appears HTML-encoded and no raw `<script>` tag is present.
21. AC21: Given the entry script and mailbox core, when their command names are read from the
    AST, then no command uses a write verb (`Set-`, `New-`, `Remove-`, `Add-`, `Enable-`,
    `Disable-`, `Update-`, `Clear-`, `Restore-`, `Start-`, `Stop-`) outside a short allowlist
    of local helpers (`New-Object`, `New-Item` for the output folder, `Add-Member`,
    `Set-Clipboard`, `Set-Content`, `Add-Content`), and no body-reading cmdlet
    (`Search-Mailbox`, `New-ComplianceSearch`, `Export-*`, Graph `/messages`) appears.
22. AC22: Given no Exchange session exists, when the check connects and finishes, then
    `Disconnect-ExchangeOnline` is called once; given a session already existed, then it is
    reused and not disconnected.
23. AC23: Given `ExchangeOnlineManagement` is installed on the test machine, when the stub
    parameter names used by the tests are compared with `Get-Command` on the real cmdlets,
    then every stubbed parameter exists (test skips with a reason when the module is absent).
24. AC24: Given `-LoadFunctionsOnly`, when the script is dot-sourced, then the mailbox
    functions are defined and neither `Connect-ExchangeOnline` nor any `Get-EXO*` is called.
25. AC25: Given the repo `.gitignore`, then the tool's case/report output folder pattern is
    listed under "Customer data".
26. AC26 (only if Q1 = A): Given unified audit log records within `-RecentDays` for
    `New-InboxRule`/`Set-InboxRule`/`UpdateInboxRules` or `Add-MailboxPermission`/
    `Add-RecipientPermission`/forwarding or send-on-behalf `Set-Mailbox` on this mailbox,
    when signs are evaluated, then a `RecentRuleChange` or `RecentDelegateChange` sign is
    raised with the time and actor; given the audit search fails or auditing is off, then
    "Recent changes" is listed under could-not-check (and AC16's partly-checked rule applies).

## Out of scope
- Any remediation: no removing rules, forwarding, permissions; no password reset; no session
  revoke; no block sign-in. Also no `-CaptureEvidence` hashed evidence folder (original pitch;
  not in the approved reshape).
- Takeover risk scoring (Low/Medium/High). CIPP's BEC report does that (D-003).
- MFA-method changes, sign-in logs, risky users, OAuth app consents (CIPP BEC and SQ-002 cover
  these).
- Message bodies, attachments, `Get-MessageTraceDetailV2` hop detail, and traces older than
  10 days or chained multi-window traces.
- Outbound spam policy / auto-forwarding block state for the tenant.
- The leaver mode (I-10), a GUI, bulk mailboxes, and on-premises Exchange.
- Running the SQ-002 sign-in verdict from this script (separate entry point).

## Approach
- **Location:** the folder SQ-002 creates (name fixed by `squad/specs/SQ-002.md`; the card
  calls it the "M365 user check" folder). Add `Get-M365MailboxCheck.ps1` (entry) and
  `MailboxCheck.Core.ps1` (pure functions). The entry script dot-sources SQ-002's core for the
  tenant banner, connection context and result/gate shape, and SQ-001's `CaseKit.ps1` for the
  ticket note, stamp and `ConvertTo-HtmlSafe`. Mirrors the core/UI split of
  `M365-SyncedUserFixes/SyncedUserFixes.Core.ps1` and `-LoadFunctionsOnly` from
  `AD-UserQuickCheck/Get-ADUserQuickCheck.ps1`.
- **Connection:** `Import-Module ExchangeOnlineManagement` in try/catch (no `#Requires
  -Modules`), reuse an existing session if `Get-ConnectionInformation` shows one, otherwise
  `Connect-ExchangeOnline -ShowBanner:$false` as in
  `Get-M365SecurityEvidence/Get-M365SecurityEvidence.ps1` line 557. Banner from the connection
  info (tenant, UPN) plus `Get-OrganizationConfig`/`Get-AcceptedDomain`.
- **Collection, one try/catch per section** (each yields `Checked` or `CouldNotCheck` +
  reason): `Get-EXOMailbox` (type, forwarding, send-on-behalf, archive, holds, quotas),
  `Get-EXOMailboxStatistics` (+ `-Archive`), `Get-EXOMailboxPermission`,
  `Get-EXORecipientPermission`, `Get-InboxRule -Mailbox -IncludeHidden`, `Get-AcceptedDomain`,
  `Get-MessageTraceV2` (two queries, single window, ≤10 days), and if Q1 = A,
  `Search-UnifiedAuditLog` for the listed operations over `-RecentDays`.
- **Pure functions in the core:** `Get-MailboxDelegates`, `Test-ExternalAddress` (against
  accepted domains), `Get-InboxRuleSigns`, `Get-ForwardingSigns`,
  `Get-MailboxCheckAssessment` (verdict, signs, could-not-check, exit code; same shape idea as
  `Get-QuickCheckAssessment`), `ConvertTo-MailboxCheckHtml`, `Get-MailboxCheckNote`.
- **Output:** console with `[PASS]/[WARN]/[FAIL]/[INFO]`, HTML + CSVs (rules, delegates,
  trace) under `-OutputPath` (default current dir) with `yyyy-MM-dd_HHmmss` names, ticket note
  via CaseKit. `.gitignore` gets the output pattern. Parameters: `-Identity` (mandatory),
  `-TraceDays` (`[ValidateRange(1,10)]`, default 7), `-RecentDays` (if Q1 = A), `-OutputPath`,
  `-TicketNumber`, `-NoTrace`, `-LoadFunctionsOnly`.
- **Docs:** README in the folder (roles needed, what "partly checked" means, the CIPP next
  step), a row in `ServiceDesk-Toolkit/README.md` ("Mail going missing / who can see this
  mailbox?", Changes anything? No), root `README.md` index. The folder is already in the bundle
  via SQ-002.
- **Verify on Microsoft Learn before coding and cite in code and `.NOTES` REFERENCES:**
  `Get-InboxRule` (`-IncludeHidden`, the role limitation for View-Only Organization Management
  and Global Reader, action property names, how the built-in junk rule appears), `Get-EXOMailbox`
  and `Get-EXOMailboxStatistics` property names (`ForwardingSmtpAddress`, `ForwardingAddress`,
  `DeliverToMailboxAndForward`, `GrantSendOnBehalfTo`, `ArchiveStatus`, `LitigationHoldEnabled`,
  `InPlaceHolds`, `RecipientTypeDetails`), `Get-EXOMailboxPermission`,
  `Get-EXORecipientPermission`, `Get-MessageTraceV2` (minimum module version, roles, 90-day /
  10-day / result-size / 100-queries-per-5-minutes limits, output field names),
  `Get-ConnectionInformation`, and (if Q1 = A) `Search-UnifiedAuditLog` operations, record
  field names and the audit role. Well-known folder names for AC10 should be matched on the
  folder identity/type, not the localized display name, where Learn allows.
- **Floor:** `#Requires -Version 5.1` (ExchangeOnlineManagement needs 5.1; root CLAUDE.md allows
  5.1 for tools that run on admin workstations). Script saved UTF-8 with BOM if it contains
  non-ASCII.

### Assumed by the squad
- **Banner vs "first line":** console prints the tenant banner on connect, before any lookup
  (D-002's wrong-tenant guard), and the verdict block's first line is the takeover line
  (backlog). In HTML and the ticket note the verdict is first and the SQ-001 stamp (tenant,
  account) follows it. Both owner requirements are met; neither is reordered.
- **Exchange-only, no Graph:** every fact listed comes from ExchangeOnlineManagement, so no
  Graph consent is added. Reason: least privilege (personal-data profile) and fewer moving parts.
- **Separate `MailboxCheck.Core.ps1`** instead of growing SQ-002's core. Reason: SQ-002's
  tests stay untouched; same split as SyncedUserFixes.Core.
- **Hidden non-system rules are a takeover sign.** Reason: hidden rules are a known BEC
  technique and fall under "rules that hide mail"; the built-in junk rule is excluded (AC11).
  If Learn shows no reliable way to tell the junk rule apart, hidden rules are listed as facts
  only and the spec is revised.
- **"Hides mail" set** = move to RSS Feeds, RSS Subscriptions, Conversation History, Deleted
  Items, Junk Email, Archive, or any move plus mark-as-read. Reason: the folders commonly used
  in BEC rules; one place in the core to extend.
- **External** = recipient domain not equal to or a subdomain of an accepted domain. Reason:
  `Get-AcceptedDomain` is the tenant's own definition.
- **Trace default 7 days, max 10, one window per direction, no chaining.** Reason: one
  `Get-MessageTraceV2` query covers at most 10 days; two queries stay far below the rate limit.
- **Exit codes** 0 clean, 1 possible takeover, 2 partly checked, 3 could not run. Reason:
  extends AD-UserQuickCheck's 0/1 so scripts can tell a blind run from a clean one.
- **Paste-safe note** shows sign kinds, rule names, and external domains only; no rule
  conditions, full addresses or trace rows. Reason: I-03 paste-safe mode and the I-02 card's
  personal-data note; full details stay in the local report.
- **Disconnect only what we connected** (AC22). Reason: personal-data profile asks to
  disconnect, but killing a tech's existing session mid-ticket is hostile.
- **Missing licence** (no mailbox, or no archive) reads as a fact ("No archive"), not a
  failure; a missing role reads as could-not-check with the role named. Reason: backlog
  "partly checked when a role or licence is missing" applies to the tool's ability to look.
- **Depends on SQ-001 and SQ-002 being merged first.** If SQ-002's core does not expose a
  banner/connection helper usable without Graph, the builder adds an Exchange-only banner
  function to `MailboxCheck.Core.ps1` rather than editing SQ-002's core.

## Risk and safety notes
- **personal-data** applies strongly: rule conditions can hold client keywords, trace rows
  hold addresses. No bodies (AC21), note redaction (AC19), HTML encoding (AC20), output
  gitignored (AC25), synthetic fixtures only, no credentials stored or logged.
- **Read-only under a write-capable role:** `Get-InboxRule` does not work for Global Reader or
  View-Only Organization Management (per Learn, to be re-cited), so the tech's account can
  change mailboxes. The static verb test (AC21) is the guard that the tool itself never does.
- **False all-clear during a compromise** is the costliest failure; AC16-AC18 make
  "partly checked" structural. The clean wording appears only when every sign section ran.
- **Destructive-operations / system-configuration:** not applicable (no writes).
