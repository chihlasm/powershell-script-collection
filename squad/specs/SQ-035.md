# SQ-035 · Smoke-test start mode for AD-Audit GUI

- status: ready
- feature: Squad tooling
- size: M
- risk: medium
- touches: `AD-Audit/Show-ADAuditGUI.ps1` (param block, startup restructured into functions, new
  smoke region), `AD-Audit/README.md`, new suite `AD-Audit/Tests/Show-ADAuditGUI-SmokeTest.Tests.ps1`,
  shared runner `Tests/Invoke-SmokeTest.ps1` (one target line plus a "does the target declare
  -SmokeTest" check) and `Tests/Invoke-SmokeTest.Tests.ps1`

## Summary (plain English)
The AD Audit window (`Show-ADAuditGUI.ps1`) gets the same "smoke test" start that the Folder
Permission Manager got in SQ-029: the real window is built and shown off-screen, a background
check runs, the window closes itself and the script prints PASS or FAIL. It never runs an audit,
never loads the ActiveDirectory module, never contacts a domain controller and writes no file.
The repo's smoke runner gets it as its second target, and also learns to refuse a GUI that has no
smoke mode instead of opening it for real.

## What users will be able to do
- Michael (or the build gate, once `smokeCommand` is set) runs
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tests\Invoke-SmokeTest.ps1` and gets a
  `[PASS] Show-ADAuditGUI.ps1: ...` line alongside the Folder Permission Manager one, or a `[FAIL]`
  line saying what went wrong (window not shown, background check failed, the GUI and
  `Invoke-ADAudit.ps1` disagree on parameters or section names, ActiveDirectory was loaded, a
  message box or an audit run was triggered).
- A tech can run `.\Show-ADAuditGUI.ps1 -SmokeTest` on a workstation to check a copied AD-Audit
  folder starts there, without touching the domain or leaving files behind.
- Normal starts of the AD Audit window and the "Run Audit" button behave exactly as before.
- If someone adds a GUI to the runner's list that has no `-SmokeTest` switch, the runner reports
  it as failed without starting it (today such a GUI would open on screen and hang the gate until
  its time limit).

## Approach
**Starting point.** `Show-ADAuditGUI.ps1` is a 300-line top-level WinForms script: no param block,
no functions apart from `Add-LogMessage`, no `-LoadFunctionsOnly`. Its startup does no elevation,
mutex, log, settings, drive, network or AD access; AD is touched only when "Run Audit" starts
`Invoke-ADAudit.ps1` in a background STA runspace, and "..." opens a `FolderBrowserDialog`. So the
smoke mode is mostly about proving the window comes up and making sure no user-reachable path can
start an audit, open a dialog or a message box while it runs. Because the script has no param
block, passing `-SmokeTest` to it today is silently ignored and the real window opens on screen:
the exact gap the SQ-029 review flagged for the runner.

**App restructure (behaviour-preserving, not a rewrite).** Follow the FPM pattern (D-061):
- Add `[CmdletBinding()] param([switch]$SmokeTest, [switch]$LoadFunctionsOnly)`, full help for both,
  an `.EXAMPLE`, and a `.NOTES` "Smoke test" paragraph: files written none, AD not loaded, no DC
  contacted, plus a REFERENCES block (WinForms `Form.Shown`, `Control.DrawToBitmap`,
  `SystemInformation.VirtualScreen`, `Form.StartPosition`, `Form.ShowInTaskbar`, the
  `ADPS_LoadDefaultDrive` environment variable on Learn).
- First statement: `$script:SmokeMode = $SmokeTest.IsPresent`; second: in smoke mode
  `$env:ADPS_LoadDefaultDrive = '0'` (process scope only, belt and braces if anything autoloads AD).
- Move the form build into `New-AuditForm` (returns a model: Form, TxtOutput, TxtDomain, NumDays,
  CboFormat, ChkSkipBrowser, SectionCheckboxes, BtnRun, TxtLog, SyncHash), keeping the `$sections`
  literal and every label, size and position as today. Event handlers call the functions below.
- Change chokepoint: `Start-AuditRun -Model` holds the Run Audit logic; in smoke mode it refuses
  first (AC6), before reading the form or creating a runspace. Runspace creation moves to
  `New-AuditRunspace` (STA, used by both Run Audit and the probe). `Select-OutputFolder` (the "..."
  button) and `Show-AuditMessage` (the only MessageBox) refuse in smoke mode. These are the only
  three user-reachable actions besides Close and the Select/Deselect links (which only tick boxes).
- `Show-AuditForm -Form` is the seam that calls `ShowDialog()`.
- `#region Smoke test`: `$script:SmokeDeadline` (30 s), `$script:SmokeFailures`, `$script:SmokeState`,
  `Add-SmokeFailure` (de-duplicating, per the SQ-029 review), `Get-SmokeVerdict`,
  `Get-SmokeTickAction`, `Set-SmokeWindowMode` (Manual position beyond the virtual screen's top-left
  minus the form size, `ShowInTaskbar = $false`), `$script:SmokeProbeWork`, `Start-SmokeProbe`.
  Same names and shapes as the FPM versions so a later shared piece is easy, but each tool keeps its
  own copy (self-contained folders).
- `if ($LoadFunctionsOnly) { return }`, then the main region: `Add-Type` WinForms/Drawing,
  `EnableVisualStyles`, `New-AuditForm`; in smoke mode `Set-SmokeWindowMode`, a `Shown` handler that
  records render time, calls `$form.DrawToBitmap` into an in-memory bitmap (positive proof the
  controls paint, independent of the off-screen position; disposed, never saved) and starts the
  probe, plus a 200 ms `System.Windows.Forms.Timer` that polls the probe and applies
  `Get-SmokeTickAction` (`$form.Close()` on Close/TimedOut). After `Show-AuditForm` returns, smoke
  mode writes the verdict lines (with `-AdModuleLoaded` from `Get-Module -Name ActiveDirectory`) and
  `exit`s with its code; the normal path ends as today.
- No `Add-Type -TypeDefinition`/C# (compiling writes to `%TEMP%`, breaking "writes no file").

**Runner (`Tests/Invoke-SmokeTest.ps1`).** Add `'AD-Audit\Show-ADAuditGUI.ps1'` to
`$script:DefaultTargets`. Add `Test-SmokeTargetDeclaresMode -Path` (parser only: the script's param
block has a parameter `SmokeTest` whose static type is `[switch]`), called by `Invoke-SmokeTarget`
before `Get-SmokeCommandLine`; a missing file or no declaration gives Failed without a launch.
Tighten the pass check to `^\s*\[PASS\] <name>:` (SQ-029 review follow-up), and keep the runner pure
ASCII and 5.1.

**Sibling conflict (SQ-031..SQ-034, SQ-036).** Every sibling adds one line to
`$script:DefaultTargets` and edits the same runner suite, and each one needs the declares-mode
check and the per-target test changes below. D-061 orders SQ-031..SQ-033 first, so SQ-035 will
probably land after some of them. Rule for the implementer: if `Test-SmokeTargetDeclaresMode`, the
`[PASS] <name>:` check and the per-target assertions already exist on the base branch, reuse them
and add only the AD-Audit line and AC16-AC20; otherwise add them here. Expect a merge conflict on
the target list and the runner suite; resolve by keeping every target line.

**Existing runner tests.** Adding a second default target changes call counts the SQ-029 tests pin
for "the default list" (AC21 expects `Start-SmokeProcess`/`Stop-SmokeProcess` exactly once; AC22
expects one launch), and the new check refuses AC21/AC22's non-existent `$TestDrive` paths. Fix
without weakening: the suite's `BeforeEach` adds `Mock Test-SmokeTargetDeclaresMode { $true }`
(test setup, overridden in AC17), and the default-list assertions in AC21/AC22 become per-target
`-ParameterFilter` assertions (exactly once for the FPM path, exactly once for the AD-Audit path,
each timed-out child killed by its own process object). No assertion is removed. The real-launch
helper `Invoke-RealRunner` redirects `LOCALAPPDATA`/`TEMP`/`TMP` into `$TestDrive` and sets
`ADPS_LoadDefaultDrive=0` for every Integration test (SQ-029 review follow-up), unless a sibling
already did.

**Docs.** `AD-Audit/README.md`: "Smoke test" section (what it proves, what it does not touch, runner
command, exit codes 0/1 and runner 0/1/2) and the two new parameters in the files/parameters table.
Root README unchanged.

## Decisions
### Confirmed by the owner
- D-061: each GUI gets its own smoke-mode item after SQ-029, added to the runner's list in one line.
- D-062: the guard rule against agents running `Tests\Invoke-SmokeTest.ps1` by hand is added at
  /squad:configure, not in this item.
- SQ-029 (spec and review): positive proof (`[PASS]` line plus exit 0), app deadline 30 s, runner
  timeout 90 s, gate 120 s; message boxes, error lines and change actions count as smoke failures.
- D-069 (2026-11-11): Q1 = A, accept a brief focus steal (real ShowDialog off-screen). 2026-11-11 plan: depends on SQ-031 (shared runner changes, see Revision notes).

### Assumed by the squad
- Restructuring the script into functions is required, not optional. Reason: the in-process tests
  need `-LoadFunctionsOnly` and seams (`Show-AuditForm`, `Start-AuditRun`, `New-AuditRunspace`); SQUAD.md
  "Logic separated from collection and UI". Not a REWRITE: same controls, texts and behaviour, pinned
  by AC13-AC15.
- "Directory reads" in the backlog text means Active Directory for this tool: smoke never loads the
  module or contacts a DC (AC3, AC5, AC8). Parsing the tool's own `Invoke-ADAudit.ps1` is allowed:
  PowerShell reads the GUI script itself to start, and the parse is what catches GUI/CLI drift that
  would break every Run Audit.
- The probe parses `Invoke-ADAudit.ps1` rather than dot-sourcing it with `-LoadFunctionsOnly`.
  Reason: dot-sourcing runs its top-level code; parsing executes nothing.
- Rendered = `Shown` fired and `DrawToBitmap` succeeded. Reason: WinForms has no `ContentRendered`;
  an off-screen window may get no `Paint`, while `DrawToBitmap` forces every control to paint in
  memory.
- `$env:ADPS_LoadDefaultDrive = '0'` in smoke mode, plus a verdict failure if ActiveDirectory got
  loaded. Reason: caller's instruction and SQUAD.md test rule; a positive check beats trusting that
  nothing autoloads.
- Run Audit, Browse and the message box are refused at their functions, not only at the button.
  Reason: SQ-029 destructive-operations lesson "enforce at the chokepoint"; a keystroke reaching the
  off-screen form can click a button.
- No pre-flag startup path exists after the change (AC2). Reason: SQ-029 lesson "pre-flag startup
  paths honour the mode"; today's GUI has no dependency check that could show a box before the flag.
- The runner checks the target declares `[switch]$SmokeTest` with the parser, and a missing file is
  refused before launch. Reason: SQ-029 review follow-up; this GUI is the concrete case (no param
  block today).
- The pass check requires `[PASS] <file name>:`. Reason: SQ-029 review follow-up; with two targets
  a loose check could pass one target on another's line.
- Integration tests redirect `LOCALAPPDATA`/`TEMP`/`TMP` and set `ADPS_LoadDefaultDrive=0` for the
  child. Reason: SQ-029 review follow-up and SQUAD.md "Tests never touch real user-facing state".
- Exit codes match FPM: app 0/1, runner 0/1/2. Reason: one runner, one contract.
- No `-LogFolder`/`-DriveMap`-style refusals: this GUI has no such parameters.

## Risk and safety notes
- read-only-advisory: AD-Audit is "Changes anything? No"; this item adds no write-capable call. The
  only writes the GUI can make (audit reports, browser open) sit behind `Start-AuditRun`, which smoke
  refuses.
- destructive-operations (SQ-029 additions): chokepoint enforcement (AC6, AC7), pre-flag paths
  (AC2), runner verifies the target declares the mode (AC17, AC20), Integration tests redirect
  LOCALAPPDATA/TEMP (AC19). "Nothing changes" mode lists startup writes in help: none (AC1, AC19).
- Real systems (SQUAD.md): no test or smoke run loads ActiveDirectory or contacts a DC; throwing
  stubs and `ADPS_LoadDefaultDrive=0` in every suite. Agents never launch the GUI or the real runner
  (`*GUI.ps1` is covered by `guard.appLaunchPatterns`; D-062 covers the runner once configured).
- The restructure touches the Run Audit path of a tool that reads the whole domain; AC13-AC15 pin
  it, and a real audit run is on Michael's try-list.
