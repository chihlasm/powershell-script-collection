# SQ-001 · Ticket note from every quick check

- status: ready
- size: L (proposed split below; each half is M)
- risk: medium
- touches: new shared kit `CaseKit.ps1` (copied per folder), new `TicketNote/` folder (joiner),
  AD-UserQuickCheck, Network-QuickCheck, Citrix-FSLogix-Triage, ServiceDesk-Toolkit build
  manifest and README, repo-wide parity test, `.gitignore`

## Summary (plain English)
After every quick check, the tool writes a short ticket note with four parts (Checked, Ruled out,
Could not check, Next step) and a stamp saying where, by whom, when, and whether anything was
changed. The note is copied to the clipboard ready to paste into ConnectWise. With
`-TicketNumber`, every tool's note and report land in one ticket folder, and a small joiner glues
them into one note. A check only appears under "Ruled out" when the tool actually managed to look.
If it could not look, the check goes under "Could not check".

## What users will be able to do
- Run AD-UserQuickCheck, Network-QuickCheck or Citrix-FSLogix-Triage as today. When the run ends,
  the console says `[INFO] Ticket note copied to the clipboard` and (when a folder is in play)
  `[INFO] Ticket note saved: <path>`. Pasting into ConnectWise gives:

  ```
  [Ticket note] AD-UserQuickCheck: Can Jane Doe sign in right now? NO

  Checked:
  - AD account jdoe in contoso.com, on 3 of 4 domain controllers.
  - PROBLEM: Their password expired on 2026-10-10.
  Ruled out:
  - Account is turned on.
  - Account does not expire.
  Could not check:
  - DC03.contoso.com: wrong-password count and last sign-in (could not reach it).
  Next step:
  - Reset their password (Set-ADAccountPassword) or have them change it from a signed-in PC. ...

  Domain: contoso.com | Ran by: CONTOSO\jtech on WS-114 | 2026-10-17 09:30:12 (UTC+01:00) | Changed anything: No
  Evidence: UserQuickCheck_jdoe_2026-10-17_093012.html, UserQuickCheck_jdoe_2026-10-17_093012.csv
  ```
- Add `-TicketNumber 482113` to any of the three tools. The tool's reports and its note go into
  `<root>\Ticket_482113\` (root: see owner question Q1).
- Run `TicketNote\Join-TicketNotes.ps1 -TicketNumber 482113`. It asks for "What did the user
  report?" and "What did you already try by hand?" (Enter skips either one). It then writes one
  combined note into the ticket folder and copies it to the clipboard.
- Add `-NoClipboard` to leave the clipboard alone. AD-UserQuickCheck gains `-PassThru` and
  `-Quiet`, like the other two tools.

## Acceptance criteria
Part A: the kit, the joiner, and AD-UserQuickCheck (stays SQ-001 if the split is accepted)

1. AC1_GatedOutCheckNeverRuledOut: Given a `Clear` item created without `-CouldLook` (or with
   `-CouldLook $false`), when `New-TicketNote` builds the note, then the item's text appears under
   "Could not check" and the "Ruled out" section does not contain it.
2. AC2_ConfirmedClearIsRuledOut: Given a `Clear` item with `-CouldLook $true`, when the note is
   built, then it appears under "Ruled out" and not under "Could not check".
3. AC3_NoteLayout: Given items of every kind and two next steps, when `ConvertTo-TicketNoteText`
   runs, then the lines are, in order: the headline `[Ticket note] <Tool>: <Headline>`, a blank
   line, then `Checked:`, `Ruled out:`, `Could not check:`, `Next step:`. Each entry is `- <text>`.
   Problem/Warning/Info entries are prefixed `PROBLEM: `/`WARNING: `/`INFO: ` and listed in that
   order after the scope line. An empty section shows `- (none)`. Then come a blank line, the
   stamp line, and the evidence line.
4. AC4_StampReadOnly: Given `New-TicketNoteStamp -ScopeLabel Domain -Scope contoso.com` with
   injected user `CONTOSO\jtech`, machine `WS-114` and a fixed time, then the stamp line is exactly
   `Domain: contoso.com | Ran by: CONTOSO\jtech on WS-114 | 2026-10-17 09:30:12 (UTC+01:00) | Changed anything: No`.
   A `-RunAs` value is appended as ` (as <RunAs>)` after the machine name.
5. AC5_StampChangedNeedsLog: Given `-Changed` without `-ChangeLogPath`, then `New-TicketNoteStamp`
   throws. With both, the stamp ends `Changed anything: Yes - change log: <path>`.
6. AC6_PasteSafeRedaction: Given entries containing `10.1.2.3`, `10.1.2.3:445`, `fe80::1`,
   `[::ffff:10.0.0.5]:445`, `\\fs01\profiles$\jdoe` and an evidence path `C:\x\y\Report.html`,
   when the note is rendered paste-safe, then every IP becomes `[IP removed]`, the UNC path becomes
   `[share path removed]`, the evidence shows only `Report.html`, and the headline is unchanged.
   When it is not rendered paste-safe, the text is unchanged except that evidence still shows file
   names only. (Which mode is the default depends on owner question Q3.)
7. AC7_NoteFileUtf8Bom: Given a note containing `Müller`, when `Save-TicketNote` writes it, then
   the file starts with the UTF-8 BOM (EF BB BF) and reads back with `Müller` intact.
8. AC8_NoteFileNamesDoNotCollide: Given two notes from the same tool with the same timestamp, when
   both are saved to one folder, then two files exist: `Note_<yyyy-MM-dd_HHmmss>_<Tool>.txt` and
   `..._<Tool>_2.txt`.
9. AC9_ClipboardFallback: Given `Get-Command Set-Clipboard` finds nothing, when
   `Copy-TicketNoteToClipboard` runs, then the WinForms wrapper (`Invoke-WinFormsClipboard`) is
   called once with the full text and the function returns `$true`.
10. AC10_ClipboardFailureIsNotFatal: Given both `Set-Clipboard` and the WinForms wrapper throw (an
    MTA host or a host with no desktop), when `Copy-TicketNoteToClipboard` runs, then it returns
    `$false` and does not throw.
11. AC11_NeverClipExe: Given the text of `CaseKit.ps1` and `Join-TicketNotes.ps1`, then neither
    contains `clip.exe` or a pipe to `clip`.
12. AC12_TicketFolder: Given `Resolve-TicketFolder -TicketNumber 482113 -Root $TestDrive`, then
    `$TestDrive\Ticket_482113` exists and its path is returned. Given `..\x`, `48/1`, an empty
    string or a 33-character value, then the function throws and creates nothing.
13. AC13_KitStaysOnPs3: Given `CaseKit.ps1`, then it declares `#Requires -Version 3.0`,
    `Get-PSVersionFloor` reports a CodeFloor of 3.0, and the file is pure ASCII.
14. AC14_KitCopiesIdentical: Given every `CaseKit.ps1` in the repo (excluding `dist/`,

## Approach

### The kit: `CaseKit.ps1` (pinned interface; SQ-002 to SQ-009 code against this)
Canonical copy: `TicketNote/CaseKit.ps1`. Identical copies go in `AD-UserQuickCheck/`,
`Network-QuickCheck/` and `Citrix-FSLogix-Triage/`. `#Requires -Version 3.0`, pure ASCII, no
`::new()`, no classes. Every function is pure apart from the three that write (Save, Copy,
Resolve-TicketFolder), and all injectable values are parameters.

| Function | Parameters | Returns |
|---|---|---|
| `New-TicketNoteItem` | `-Kind Problem\|Warning\|Info\|Clear\|NotChecked` (mandatory), `-Text` (mandatory), `-CouldLook [bool]` (default `$false`) | `[PSCustomObject]@{ Kind; Text; CouldLook }` |
| `New-TicketNoteStamp` | `-ScopeLabel Domain\|Tenant\|Computer`, `-Scope`, `-RunAs`, `-Changed` (switch; parameter set needs `-ChangeLogPath`), `-ChangeLogPath`, `-Now [datetime]`, `-UserName`, `-ComputerName` (defaults `$env:USERDOMAIN\$env:USERNAME`, `$env:COMPUTERNAME`) | `[PSCustomObject]@{ ScopeLabel; Scope; RanBy; Machine; RunAs; Time; Changed; ChangeLogPath }` |
| `New-TicketNote` | `-Tool` (folder name, e.g. `AD-UserQuickCheck`), `-Headline`, `-ScopeLine`, `-Items [object[]]`, `-NextSteps [string[]]`, `-Stamp`, `-EvidencePaths [string[]]` | `[PSCustomObject]@{ Tool; Headline; ScopeLine; Checked; RuledOut; CouldNotCheck; NextSteps; Stamp; EvidencePaths; CreatedAt }`. This function is the gate. A `Clear` item goes to RuledOut only when `CouldLook -eq $true`. Otherwise it goes to CouldNotCheck with the suffix ` (the tool could not confirm it was able to look)`. |
| `ConvertTo-TicketNoteText` | `-Note`, `-PasteSafe [switch]` | `[string[]]` lines in the AC3 layout |
| `Protect-TicketNoteText` | `-Line [string]` | the redacted line (AC6 rules) |
| `Resolve-TicketFolder` | `-TicketNumber` (`^[A-Za-z0-9][A-Za-z0-9_-]{0,31}$`), `-Root` | full path of `<Root>\Ticket_<n>`, created if missing |
| `Get-TicketNoteDefaultRoot` | none | the default root (owner Q1) |
| `Save-TicketNote` | `-Note`, `-Folder`, `-PasteSafe` | path of `Note_<yyyy-MM-dd_HHmmss>_<Tool>[_n].txt` (UTF-8 with BOM through `[System.IO.File]::WriteAllLines` and `New-Object System.Text.UTF8Encoding($true)`) |
| `Copy-TicketNoteToClipboard` | `-Text [string]` | `$true`/`$false`; never throws |
| `Invoke-WinFormsClipboard` | `-Text` | wrapper for `Add-Type -AssemblyName System.Windows.Forms; [System.Windows.Forms.Clipboard]::SetText($Text)`, kept separate so tests can mock it |
| `Publish-TicketNote` | `-Note`, `-Folder` (may be empty), `-PasteSafe`, `-NoClipboard` | `[PSCustomObject]@{ NotePath; Copied; Lines }`. Saves when `-Folder` is given, copies unless `-NoClipboard`, and writes the two `[INFO]` lines. If neither the save nor the copy worked, it prints the note to the console so it is never lost. |

Clipboard order inside `Copy-TicketNoteToClipboard`:
`if (Get-Command Set-Clipboard -ErrorAction SilentlyContinue) { Set-Clipboard ... } else { Invoke-WinFormsClipboard ... }`.
The whole thing sits in try/catch. If `Set-Clipboard` throws, the WinForms wrapper is tried, and if
that fails too the function returns `$false`. The `Get-Command` guard is the form that
`Tests/PSVersionFloor.Analyzer.ps1` (`Test-InsideGetCommandGuard`) accepts on a 3.0 floor. Cite
in the code: Set-Clipboard 5.0
(https://learn.microsoft.com/powershell/module/microsoft.powershell.management/set-clipboard?view=powershell-5.1),
STA default since 3.0
(https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1),
and why not clip.exe (`$OutputEncoding` ASCII in 5.1,
https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_preference_variables?view=powershell-5.1).
Add these links to each adopting script's `.NOTES` REFERENCES.

### How a tool plugs in (the pattern SQ-002 and later follow)
1. Near the top of the script, before `if ($LoadFunctionsOnly) { return }`:
   `$kit = Join-Path $PSScriptRoot 'CaseKit.ps1'; if (Test-Path -LiteralPath $kit) { . $kit } else { $script:CaseKitMissing = $true }`.
   If the kit is missing, the tool prints `[WARN] CaseKit.ps1 is missing from this folder - no
   ticket note this time.` and otherwise runs as today.
2. New parameters: `-TicketNumber` (string, same ValidatePattern) and `-NoClipboard`.
   AD-UserQuickCheck also gets `-PassThru` and `-Quiet`, matching the other two tools' help text
   and behaviour.
3. A per-tool adapter `ConvertTo-<Tool>TicketNote -Result $result -EvidencePaths ...` maps the
   tool's own result to kit items. This function holds the tool's gate decisions, and the unit
   tests cover it.
4. Folder rule: with `-TicketNumber`, folder = `Resolve-TicketFolder -Root (OutputPath if given,
   else Get-TicketNoteDefaultRoot)`, and the tool's existing reports are written there too. With
   only `-OutputPath`, the note is saved beside the reports. With neither, see owner Q2.
5. The result object gains a `TicketNote` property (the note object). The `-PassThru` result keeps
   every existing property, so older callers keep working.
6. The clipboard is skipped under `-NoClipboard` or `-Quiet`, because `-Quiet` means another script
   is the caller.

### Gate mapping per tool
- **AD-UserQuickCheck.** `Get-QuickCheckAssessment` gains a `Cleared` list of
  `{ Code; Message; CouldLook }`, built next to the existing `Passes` strings. `Passes` stays
  as it is for the console and HTML. CouldLook is `$true` except in two cases: `NotLocked` is
  `$false` when `PdcNote` is set, and `NoBadPasswords` is `$false` when `UnreachableDCs` is not
  empty. Reasons map as follows: Blocker becomes Problem, Probable becomes Warning, Warning stays
  Warning, and Info stays Info. `DcUnreachable` and `PdcFallback` become NotChecked, and so does
  each `Facts.Notes` entry (group count or policy not readable). Next steps are the Actions of the
  Blocker and Probable reasons, deduplicated. With a YES verdict and no blockers, the next step is
  `No account problem found. Look at the device, the network or the app next (DriveMap-Diagnostics, Network-QuickCheck).`
  The scope line is `AD account <sam> in <domain>, on <checked> of <total> domain controllers.`
  The stamp's ScopeLabel is Domain, using `Get-DomainDnsFromDn`. `-Credential` gives
  `-RunAs $Credential.UserName`.
- **Network-QuickCheck.** `New-EvidenceItem` gains an optional `-NotChecked` switch, stored as a
  `NotChecked` property (default `$false`, so no change for existing callers). It is set on the
  ping-catch and route-catch items. Pass becomes Clear with `CouldLook = -not NotChecked`. Fail
  becomes Problem. A Warn without `NotChecked` becomes Warning; with it, NotChecked. The IP-target
  DNS item is dropped from the note (AC29). A missing `Get-NetRoute` adds a note-only NotChecked
  item with no new evidence item, so the verdict does not change (AC28). The next steps are the
  existing `RecommendedNextSteps`. The stamp is `-ScopeLabel Computer -Scope $env:COMPUTERNAME`,
  because the check runs from this PC.
- **Citrix-FSLogix-Triage.** The same `-NotChecked` switch on its own `New-EvidenceItem`. It is set
  on the catch paths for ping, services, registry (catch and `profileKey.Error`), event access
  (not log-missing), disks, and "no local disks returned". It is also set on the remote
  share-unconfirmed item and the Cloud Cache "not tested" item. The Status values stay as they are
  (Warn), so the verdict does not change. The FSLogix settings block (`RawOutput.Registry`) never
  goes into the note. The stamp is `-ScopeLabel Computer -Scope <target>`. The headline reuses
  `Get-TriageHeadline`.

### Joiner: new folder `TicketNote/`
`TicketNote/Join-TicketNotes.ps1` (`#Requires -Version 3.0`, dot-sources its own `CaseKit.ps1`).
It takes `-TicketNumber` (mandatory, same pattern), `-OutputPath` (root, default
`Get-TicketNoteDefaultRoot`), `-UserReported`, `-TechTried`, `-NoClipboard`, `-PasteSafe` (per Q3)
and `-LoadFunctionsOnly`. It reads `Note_*.txt` sorted by name (the timestamp comes first, so name
order is time order), skips `TicketNotes_Combined_*`, writes
`TicketNotes_Combined_<yyyy-MM-dd_HHmmss>.txt` (UTF-8 with BOM), and copies it to the clipboard.
The folder also gets a `README.md` and `Tests/`. Add it to the root `README.md` index, to the
`ServiceDesk-Toolkit/Build-ServiceDeskToolkit.ps1` manifest, and to `ServiceDesk-Toolkit/README.md`
(Changes anything? No; it only writes the combined note file).

## Decisions
### Confirmed by the owner
- D-004 split: this spec covers SQ-001 (Part A: kit, joiner, AD-UserQuickCheck) and SQ-010 (Part B: Network-QuickCheck and Citrix-FSLogix-Triage adopt the note).
- D-009 paste-safe by default; -FullDetail opts out.
- D-012 default ticket folder %USERPROFILE%\Documents\TicketNotes\Ticket_<n>.
- D-013 no note file without -TicketNumber or -OutputPath; clipboard with console fallback.
- Approved in the 2026-10-17 pitch session (BACKLOG SQ-001): four-part format, stamp,
  `-TicketNumber`, joiner, gate rule, first slice, copied kit with parity test.
- D-002 (show the account and tenant first): the stamp's `-RunAs`/`-ScopeLabel Tenant` exist so
  SQ-002 can meet it.

### Assumed by the squad
- "Ruled out" requires an explicit `CouldLook = $true`, and the default is `$false`. A forgotten
  flag therefore errs towards "Could not check", never towards a false all-clear. (Card build
  condition; P-001.)
- Gate-failed checks keep their current Warn status in the tools. Only the note moves them, so
  verdicts and exit codes do not change. (Out of scope: changing existing reports.)
- Findings go under "Checked", prefixed PROBLEM/WARNING/INFO, after a one-line scope. This matches
  the card's "a day with it" example, where findings and scope sit under Checked.
- The kit's canonical copy is `TicketNote/CaseKit.ps1`, kept in step by a byte-for-byte parity
  test. This follows the self-contained-folder rule in SQUAD.md and the
  SharedReferenceParity precedent.
- The joiner lives in a new `TicketNote/` folder that ships in the bundle, because the bundle copies
  whole folders (`Build-ServiceDeskToolkit.ps1` manifest) and the joiner needs its own kit copy.
- The ticket folder is named `Ticket_<n>`, not a bare number, so `.gitignore` can cover it, as
  `Case_*` does for lockout cases.
- Ticket numbers allow `[A-Za-z0-9_-]`, up to 32 characters, starting with a letter or digit. This
  blocks path traversal while allowing non-numeric references.
- With `-TicketNumber`, the tool's own reports also go into the ticket folder, so the note's
  evidence names resolve next to it. (The card says the note carries "the paths to the
  evidence".)
- The clipboard is on by default, `-NoClipboard` opts out, and the clipboard is skipped under
  `-Quiet` (scripted callers). The card calls the clipboard a primary output.
- Clipboard: `Get-Command Set-Clipboard` guard, then a WinForms fallback, never clip.exe. This is
  the critique's build condition and is the only form the PSVersionFloor analyzer accepts on a
  3.0 floor.
- The note file is UTF-8 with BOM. Names like Müller must survive Notepad and Windows PowerShell,
  and AD-UserQuickCheck's HTML already uses the same encoding.
- The stamp time includes the UTC offset, because tickets are read later by other people,
  possibly in another time zone. The format is the repo's `yyyy-MM-dd HH:mm:ss`.
- `-Changed` cannot be used without `-ChangeLogPath`. SQ-008 and SQ-009 must point at their change
  log, which enforces the destructive-operations rule ("each change is written to a log").
- Evidence shows file names only, never directories. The ticket folder already holds the files,
  and local profile paths add nothing to ConnectWise.
- AD-UserQuickCheck gains `-Quiet` as well as `-PassThru`, for consistency with Network-QuickCheck
  and Citrix-FSLogix-Triage, whose help text is reused.
- The headline is never redacted in paste-safe mode. It is the question the tech typed, and the
  note is useless without it.
- No note when a tool cannot start (module missing, blank target). Those runs checked nothing, and
  their console message already says what to do.

## Risk and safety notes
- **personal-data profile.** Notes and ticket folders hold client user names, host names and
  findings. They stay local (file plus clipboard; no upload). `.gitignore` gains `**/Ticket_*/`.
  `-Credential` objects and passwords never reach the note (AC24). FSLogix connection strings stay
  out (AC32). Paste-safe redaction covers IPs and share paths (AC6).
- The clipboard on a client server, inside an RDP session, may or may not reach the tech's PC,
  depending on clipboard redirection. The note file is the dependable copy, and the console says
  where it is.
- **Not destructive.** The only writes are new files in the ticket or output folder. The three
  tools stay read-only, and their stamp says `Changed anything: No`.
- The 3.0 floor risk (a 5.0 feature creeping in through the kit) is caught by AC13 and
  `Tests/PSVersionFloor.Tests.ps1`. Copies drifting apart is caught by AC14.
