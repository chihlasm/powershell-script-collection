# SQ-032 · Smoke-test start mode for CopyFileToServer

- status: ready
- feature: Squad tooling
- size: M
- risk: medium
- touches: CopyFileToServer-GUI.ps1 (new `-SmokeTest` switch, startup region, guards on every
  write/dialog/network entry point, a message-box wrapper), CopyFileToServer README,
  `Tests/Invoke-SmokeTest.ps1` (default list + "does the target declare -SmokeTest" check),
  new suite `CopyFileToServer/Tests/CopyFileToServer-SmokeTest.Tests.ps1`, edits to
  `Tests/Invoke-SmokeTest.Tests.ps1`

## Summary (plain English)
The squad's build gate starts the Folder Permission Manager for real after every change (SQ-029),
but not "Copy Files to Servers". This item gives that window the same smoke-test start: the real
app starts, draws its real window off-screen, proves its background workers run, closes itself
and prints PASS or FAIL. It reads no saved settings, writes no log or settings file, contacts no
server and opens no file dialog. The smoke runner then checks both apps, and it now refuses to
start any app that does not actually have a smoke-test switch.

## What users will be able to do
- Michael (or the gate's `smokeCommand`) runs
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tests\Invoke-SmokeTest.ps1` and gets
  a second line, `[PASS] CopyFileToServer-GUI.ps1: the window opened and closed by itself (...)`,
  or a `[FAIL]` line saying what went wrong; the runner's exit code covers both apps.
- A tech can run `.\CopyFileToServer-GUI.ps1 -SmokeTest` to check a copy of the tool starts on a
  workstation, without a window appearing, without touching the saved server list and without
  leaving a `Logs` or `State` folder behind.
- Normal starts of Copy Files to Servers are unchanged (settings remembered, console hidden,
  relaunch into STA when needed).

## Approach
**Pattern to match.** SQ-029 in `FolderPermissionManager/FolderPermissionManager-GUI.ps1`
(`#region Smoke test`, lines ~7043-7143): `Add-SmokeFailure`, `Get-SmokeVerdict`,
`Get-SmokeTickAction`, `Set-SmokeWindowMode`, `Start-SmokeProbe`, `Invoke-SmokeTick`,
`$script:SmokeState`, `$script:SmokeDeadline`. Copy these into CopyFileToServer-GUI.ps1 (folders
stay self-contained; no shared module), with `-Name` defaulting to `CopyFileToServer-GUI.ps1` and
`Add-SmokeFailure` ignoring an exact repeat. The file stays pure ASCII and `#Requires -Version 5.1`.
Place the new region among the function regions, before `if ($LoadFunctionsOnly) { return }`.

**What is different from FPM.** No core file, no elevation, no mutex, no drive map, no
`Invoke-AppShutdown`. Startup state lives next to the script (`Logs\`, `State\`), and the normal
start writes `State\settings.json` while the window is built (`& $setIf` in `New-CopyWindow`
calls `Save-Settings`) and again on close, so the guards must sit inside `Save-Settings` itself,
not around callers. There is no pool at startup; pools are created on Check connection / Copy.

**App changes.**
- Param `[switch]$SmokeTest`; help, `.EXAMPLE`, `.NOTES` "Files written: none in smoke mode" and
  REFERENCES (VirtualScreenLeft, ContentRendered; reuse FPM's URLs).
- `$script:SmokeMode = $SmokeTest.IsPresent` right after `$ErrorActionPreference`. Pre-flag
  exceptions: none (only `Join-Path`/`Split-Path` run earlier; AC3 pins it).
- `Test-SmokeBlocked -Action <text> [-Quiet]`: returns `$true` in smoke mode and, unless `-Quiet`,
  writes `[FAIL] ... <action> was triggered during the smoke test` and adds one failure. Used
  as the first statement of: `Start-CopyRun`, `Start-ConnectionCheck`, `Add-Sources`,
  `Import-ServerFile`, `Show-AddFilesDialog`, `Show-AddFolderDialog`, `Show-ImportDialog` (new:
  the Import button's inline handler body moved into a function), `Save-ServerList`,
  `Export-RunResults`, `Open-RunLog` (new: the Open log handler body moved), `Write-RunLog`
  (quiet). `Read-Settings` and `Save-Settings` return quietly (no failure). `Write-GuiError` in
  smoke mode writes the `[FAIL]` line and a failure instead of the file.
- `Show-GuiMessage -Owner -Text -Caption -Buttons -Icon`: normal mode calls
  `[System.Windows.MessageBox]::Show` exactly as today (with or without owner); smoke mode writes
  `[FAIL]`, adds a failure and returns `OK`/`Cancel`/`No`. All six current `MessageBox::Show`
  calls (Start-CopyRun x2, Clear list, Closing, Export failure, fatal catch) go through it.
- `Get-StartupAction -IsSta [-SmokeTest]` (pure). Startup region: read the apartment, call it;
  `RelaunchSta` keeps today's `Start-Process` line verbatim; `SmokeNeedsSta` writes `[FAIL] The
  smoke test needs a single-threaded apartment: start powershell.exe with -STA.` and `exit 1`.
- `Start-CopyWindow`: smoke mode skips `Read-Settings`; after `New-CopyWindow`, calls
  `Set-SmokeWindowMode`; ContentRendered runs `Start-SmokeProbe` instead of `Hide-OwnConsole`
  (which compiles C# through Add-Type, i.e. writes to TEMP) and the focus call; the existing 250 ms
  timer also calls `Invoke-SmokeTick` in smoke mode. `ShowDialog` moves into a one-line
  `Show-CopyWindow $win` so tests can build the real window without showing it.
- `Start-SmokeProbe`: sets Rendered, creates `$script:SmokePool = New-WorkerPool -Max 1`, starts
  `Start-BgTask -Command 'Format-Bytes' -Parameters @{ Bytes = 2048 }` whose OnDone sets
  ProbeOk (`$result -eq '2 KB'`), ProbeMs, ProbeDone, ProbeError. This proves the pool opens, the
  worker functions copy into the runspace, and `Update-BgTasks` delivers results, with no I/O.
- Main: in the `catch`, smoke mode adds "the app hit an error: <message>" and skips the box; in
  `finally`, `Stop-SmokeProbePool` closes the probe pool synchronously (it is idle) besides the
  existing `BeginClose` lines; then, in smoke mode only, write `Get-SmokeVerdict` lines and
  `exit` with its ExitCode (`exit N` under `-File` sets the process exit code, per the
  about_PowerShell_exe page already cited by the runner).
- README: "Smoke test" section (what it proves, what it does not touch, runner command, exit
  codes). The "Files the tool creates" section notes smoke mode creates none.

**Runner changes (`Tests/Invoke-SmokeTest.ps1`).**
- Add `'CopyFileToServer\CopyFileToServer-GUI.ps1'` to `$script:DefaultTargets`.
- `Test-SmokeTargetDeclaresSwitch -ScriptPath`: parses the file with
  `[System.Management.Automation.Language.Parser]::ParseFile`; true only when the script's
  ParamBlock has a `SmokeTest` parameter of type `switch` and the script is advanced
  (`CmdletBinding` attribute or a `Parameter` attribute), so an unknown switch cannot be silently
  ignored. `Invoke-SmokeTarget` calls it first; false or a parse/read error gives Failed without
  calling `Start-SmokeProcess`. Help `.PARAMETER ScriptPath` and `.DESCRIPTION` say so.
- Test file: AC22's count becomes `$script:DefaultTargets.Count`; its `-ScriptPath` case uses a
  fixture script; AC23 becomes AC21 (redirects LOCALAPPDATA/TEMP/TMP, expects both PASS lines);
  new AC18-AC20 and AC22.

**Sibling conflict.** SQ-031..SQ-036 each add a line to `$script:DefaultTargets`, and each will
touch `Tests/Invoke-SmokeTest.Tests.ps1` (AC22/AC23). Whichever merges first adds

same shape as this GUI ("same look as RobocopyMigration-GUI.ps1"), so its helpers will look
alike; they stay copied per folder.

## Decisions
### Confirmed by the owner
- D-061: CopyFileToServer gets its own smoke-mode item after SQ-029; the runner takes a list so
  each GUI is added in one line.
- D-062: agents are guarded from running `Tests\Invoke-SmokeTest.ps1` by hand once
  `smokeCommand` is set; unaffected by this item.
- SQ-029 (merged): the smoke design (positive proof, off-screen window, 30 s window deadline, 90 s
  runner timeout, exit codes, Integration-only real launch).
- 2026-11-11 plan: depends on SQ-031, which owns the shared runner changes (see Revision notes).

### Assumed by the squad
- Same visible behaviour and wording as SQ-029 (PASS/FAIL lines, exit codes, README section).
  Reason: D-061 says "the same way SQ-029 does".
- Settings are neither read nor written in smoke mode; `Save-Settings` and `Read-Settings` return
  quietly rather than counting as failures. Reason: backlog ("no ... settings ... reads"); the
  normal window calls `Save-Settings` during build and close (`New-CopyWindow`, Closing handler),
  so counting it would fail every run.
- Guards sit inside the functions that write, prompt, open dialogs or contact servers, plus an
  AST test that no such call exists outside them. Reason: SQ-029 checklist gap "enforce at the
  change chokepoint ... every direct UI handler that writes must also check the mode".
- Two inline handlers (Import, Open log) move into named functions so they can be guarded and
  tested. Reason: same gap; no behaviour change.
- The probe runs `Format-Bytes` in a fresh `New-WorkerPool -Max 1`. Reason: the GUI has no
  startup pool; this exercises the same pool, function copy and `Update-BgTasks` path the copy
  and check features use, without network or disk.
- `Hide-OwnConsole` is skipped in smoke mode. Reason: its `Add-Type -MemberDefinition` compiles C#
  through temp files, and the runner's child has no console window to hide.
- No pre-flag exceptions. Reason: only `Join-Path`/`Split-Path` run before the mode is captured
  (checklist gap "pre-flag startup paths honour the mode"; pinned by AC3).
- The runner's "declares -SmokeTest" check lands with this item (or is reused if a sibling landed
  it first). Reason: checklist gap; with two targets the default list is now a growing list.
- Integration tests redirect LOCALAPPDATA/TEMP/TMP for every child (AC21, AC22). Reason:
  checklist gap.
- `-SmokeTest -LoadFunctionsOnly`: LoadFunctionsOnly wins (functions defined, nothing runs).
  Reason: matches the existing guard order and FPM.
- REWRITE: no. Additive mode on an existing window; normal start pinned by AC16/AC17 and the
  existing suite.

## Risk and safety notes
- destructive-operations applies (CopyFileToServer is listed: overwrites files on many servers).
  The smoke mode is a "nothing changes" mode: its help lists startup writes, which are none (AC1,
  AC5, AC22). Copy, check, import, save, export and dialogs are refused at their entry points
  (AC7, AC10); no server is contacted (`Get-ReachProblem` and the copy/check workers are never
  started). No copy run can exist, so the Closing "copy still running" prompt cannot appear.
- Elevation, prompts and shutdown: no elevation exists in this tool; the STA relaunch never
  happens in smoke mode (AC4). The probe pool is closed synchronously before `exit`.
- system-configuration / "agents do not read this machine": settings, saved server list and
  drives are not read; every such read is faked to throw in the tests (AC5, AC7, AC8).
