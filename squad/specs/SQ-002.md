# SQ-002 · M365 user check: can this user sign in, and is it a sync problem?

- status: ready
- size: L (proposed split into SQ-002a and SQ-002b, see below; each is M)
- risk: medium
- touches: new folder `M365-UserQuickCheck/` (entry script, core, README, tests),
  `ServiceDesk-Toolkit/Build-ServiceDeskToolkit.ps1` manifest, `ServiceDesk-Toolkit/README.md`
  START HERE table and section, root `README.md` index, `.gitignore`, SQ-001's `CaseKit.ps1`
  (consumed, copied into the folder, not changed)

## Summary (plain English)
A tech types one Microsoft 365 user's sign-in name and gets a YES / NO / PROBABLY NOT answer
for Microsoft 365, with the reason in plain words and what to do next. Before any answer it
prints which client tenant and which account it is signed in to, and what it could and could
not see there (for example "Sign-in history: not available, this tenant has no Entra ID P1").
For hybrid clients it also compares the cloud account with the on-premises AD account and
says whether the problem is sync. It only reads; it never changes anything, even when the
tech signs in as the client's global admin.

## What users will be able to do
- Run `.\Get-M365UserQuickCheck.ps1 -UserPrincipalName jdoe@contoso.com` (optionally
  `-TenantId contoso.onmicrosoft.com`), sign in in the browser, and read:
  1. **Banner** (always first): tenant name, default domain, tenant ID, signed-in account and
     its admin roles, "This tool only reads", then one line per data source: Sign-in history,
     Conditional Access detail, MFA methods, Risky user, On-premises AD, each as
     available / not available (with the reason).
  2. **Verdict line**: "Can Jane Doe sign in to Microsoft 365?  NO" (colour-coded like
     AD-UserQuickCheck).
  3. **Why not** (blockers and probable causes, each with "What to do"), **Also worth knowing**
     (warnings, info), **Looks fine** (passes), **Could not check** (gated-out sources, with
     the reason), then a **Details** table for sysadmins and the recent sign-in rows.
- Get the reason for a failed sign-in in Microsoft's own words (`status.failureReason`), the
  error code, and a link to Microsoft's live lookup (`https://login.microsoftonline.com/error?code=<n>`).
- On hybrid clients, see whether the account exists on both sides, whether AD and Microsoft 365
  agree on the important fields, whether sync has run recently, whether another object holds
  the user's address, and whether the account was blocked on purpose with M365-SyncedUserFixes.
- Add `-OutputPath C:\Temp` to save an HTML report and a one-row CSV; add `-TicketNumber`
  (SQ-001) to drop the four-part ticket note into the ticket folder and onto the clipboard.
- Stop safely when the sign-in name's domain does not belong to the tenant they signed in to
  ("Wrong tenant?").

## Acceptance criteria
Part A, Graph stage (SQ-002a if split):
1. AC1_BannerPrintsFirst: Given a connected Graph context, when the check runs, then the tenant
   display name, default domain, tenant ID and signed-in account are written before any
   user lookup is made and before the verdict line, and the banner contains "This tool only reads".
2. AC2_WrongTenantStops: Given a UPN whose domain is not a verified domain of the connected
   tenant, when the check runs, then it stops with a message naming the UPN domain and the
   tenant, makes no `/users` request, and returns exit code 3.
3. AC3_ReadOnlyByConstruction: Given every `.ps1` in `M365-UserQuickCheck/`, when scanned
   statically, then every `Invoke-MgGraphRequest` uses `-Method GET`, no `New-Mg*`, `Set-Mg*`,
   `Update-Mg*`, `Remove-Mg*`, `Set-AD*`, `Enable-ADAccount`, `Unlock-ADAccount`,
   `Set-ADAccountPassword` appears, and every requested scope matches `\.Read(\.All)?$`.
4. AC4_UserNotFoundOrAmbiguous: Given no user matches the UPN (and the AD stage finds no
   on-premises account), then the result says no Microsoft 365 user matched and exits 2; given
   the fallback mail/proxy-address lookup returns more than one user, then the candidates are
   listed (name, UPN, enabled) and it exits 2 without guessing.
5. AC5_SignInBlocked: Given `accountEnabled` is false, then the verdict is NO with a "Sign-in is
   blocked" reason; the next step for a synced user points to on-premises AD (disabled account
   or the M365-SyncedUserFixes block marker), and for a cloud-only user to the admin center.
6. AC6_NoUsableLicence: Given `assignedLicenses` is empty, or `licenseAssignmentStates` holds an
   entry with state `Error`, then the verdict is PROBABLY NOT with a reason naming which case
   applies (and the error value for the second case).
7. AC7_NoMfaMethod: Given the authentication methods list holds only a password method, then a
   Warning "No MFA method registered" is added and the verdict is not changed by it.
8. AC8_NoP1IsCouldNotCheck: Given the sign-in log request fails with
   `Authentication_RequestFromNonPremiumTenantOrB2CTenant`, then the banner reads "Sign-in
   history: not available (this tenant has no Entra ID P1)", the result lists sign-in history
   under Could not check, no pass line claims there are no sign-in problems, and the verdict is
   never YES (it is the owner-chosen non-P1 label, see Q1, unless a blocker or probable cause
   was found).
9. AC9_ForbiddenIsDistinctFromNoP1: Given the sign-in log request fails with HTTP 403 for any
   other reason (role or consent), then the banner and Could not check say the signed-in
   account is not allowed to read sign-in history, with the role names that can, and the
   reason text differs from AC8's.
10. AC10_BlockingFailureCodeIsNo: Given the most recent sign-in in the window failed with
    50053, 50057, 50055, 53003 or 530035, then the verdict is NO and the reason includes the
    code, the log's `failureReason` verbatim, the number of consecutive failures before it,
    the time of the most recent one, the link `https://login.microsoftonline.com/error?code=<code>`,
    and the cited next step marked "meaning per Microsoft, may change".
11. AC11_UnmappedFailureCodeShowsMicrosoftText: Given the most recent sign-in failed with a code
    not in the next-step map (for example 50126 is mapped; use 50140 or a made-up 99999), then
    the verdict is PROBABLY NOT and the reason shows only the code, `failureReason` and the
    lookup link, with no meaning invented by the tool.
12. AC12_ConditionalAccessPolicyNamed: Given the most recent sign-in failed with 53003 and
    `appliedConditionalAccessPolicies` holds a policy with result `failure`, then the reason
    names that policy's display name.
13. AC13_ConditionalAccessDetailHidden: Given sign-in rows are returned without the
    `appliedConditionalAccessPolicies` property, then "Conditional Access detail" is listed
    under Could not check (signed-in role cannot read it), and nothing says Conditional Access
    was ruled out.
14. AC14_LatestSuccessPasses: Given the most recent sign-in succeeded and older ones failed,
    then a pass "Last sign-in succeeded at <time> (<app>)" is shown, the older failures are
    summarised as Info by code and count, and no sign-in reason makes the verdict NO.
15. AC15_NoSignInsInWindow: Given sign-in history is available but holds no rows for the window,
    then an Info line says no sign-in attempts reached Microsoft 365 in the last <Days> days,
    and it is not counted as a pass.
16. AC16_RiskyUserGatedOnP2: Given the riskyUsers request fails because the tenant has no
    Entra ID P2, then the banner reads "Risky user: not available (needs Entra ID P2)" and it is
    under Could not check; given it succeeds with `riskLevel` high or `riskState` atRisk, then a
    Warning names the risk level and state.
17. AC17_DisconnectAlways: Given any check throws after connecting, then `Disconnect-MgGraph` is
    still called once.

Part B, on-premises comparison (SQ-002b if split):
18. AC18_AdStageUnavailableStillGivesVerdict: Given the user is synced and the ActiveDirectory
    module cannot be imported or no DC answers, then the Graph verdict is still printed, the
    banner and Could not check say "On-premises AD: could not check (<reason>)", and the exit
    code comes from the Graph stage.
19. AC19_CloudOnlySkipsAd: Given `onPremisesSyncEnabled` is not true and no AD account has the
    UPN, then the result shows "Cloud-only account: sync is not involved" as a pass and
    makes no `Get-ADUser` call other than the UPN search.
20. AC20_NeverSynced: Given no Microsoft 365 user matches but an AD user with that UPN exists,
    then the verdict is NO with "This account exists in AD but not in Microsoft 365", and the
    next step names sync scope (OU filtering) and the Entra Connect check; given that AD user
    carries `msDS-cloudExtensionAttribute10 = BlockCloudSignIn`, then the reason instead says
    it was removed from Microsoft 365 on purpose by M365-SyncedUserFixes.
21. AC21_ProvisioningErrorNamesConflict: Given the cloud user's `onPremisesProvisioningErrors`
    holds an entry, then the verdict is NO and the reason shows the category, the property
    causing the error and its value.
22. AC22_AddressHeldByAnotherObject: Given the AD user's UPN or primary SMTP address is held in
    Microsoft 365 by a different object (a cloud-only user, a group or a contact), then the
    verdict is NO and the reason names that object's type and display name.
23. AC23_EnabledMismatch: Given AD says enabled and Microsoft 365 says blocked, then: with the
    BlockCloudSignIn marker present, an Info says it is blocked on purpose and the verdict
    reason's next step says to remove the marker with M365-SyncedUserFixes if that is wrong;
    without the marker, a Probable reason says AD and Microsoft 365 disagree, with the tenant's
    last sync time.
24. AC24_StaleTenantSync: Given the organization's `onPremisesLastSyncDateTime` is more than
    3 hours old, then a Warning gives its age and says sync normally runs every 30 minutes;
    given it is under 3 hours, then a pass shows the time.
25. AC25_UpnMismatch: Given the AD user (matched by on-premises SID) has a different UPN from
    the cloud user, then a Warning shows both values.

Shared output:
26. AC26_TicketNoteGateAware: Given `-TicketNumber` and a run where sign-in history was not
    available, then the SQ-001 note lists sign-in history under Could not check and never
    under Ruled out, its stamp names the tenant and signed-in account and "Changed anything: No",
    and the note text contains no IP address even when sign-in rows carry `ipAddress`.
27. AC27_HtmlEncodesGraphValues: Given a display name, failureReason or policy name containing
    `<script>`, then the HTML report contains it encoded and never raw.
28. AC28_ReportFiles: Given `-OutputPath`, then `M365UserCheck_<safe-upn>_<yyyy-MM-dd_HHmmss>.html`
    and `.csv` are written there (CSV via `Export-Csv -NoTypeInformation -Encoding UTF8`, one
    row, no IP column); given no `-OutputPath`, then no file is written apart from the
    SQ-001 note when `-TicketNumber` is set.
29. AC29_BundleAndIndex: Given the repo, then `Build-ServiceDeskToolkit.ps1`'s manifest includes
    `M365-UserQuickCheck`, the START HERE table has a "Can't sign in to Microsoft 365 /
    Outlook / Teams" row pointing to it marked "Changes anything? No", and the root `README.md`
    index lists the folder.

## Approach
**Folder and files** (one folder, two entry scripts eventually, one core; card I-01
"Packaging", critic I-01):
- `M365-UserQuickCheck/M365UserCheck.Core.ps1`: pure functions plus Graph/AD access functions,
  `-LoadFunctionsOnly` to define and return (pattern: `M365-SyncedUserFixes/SyncedUserFixes.Core.ps1`,
  `AD-UserQuickCheck/Get-ADUserQuickCheck.ps1:931`). SQ-007 adds its mailbox functions here later.
- `M365-UserQuickCheck/Get-M365UserQuickCheck.ps1`: entry script, `#Requires -Version 5.1`
  (Microsoft.Graph needs 5.1; root CLAUDE.md allows it for Graph tools; card "Floor").
  Dot-sources the core and `CaseKit.ps1`.
- `M365-UserQuickCheck/CaseKit.ps1`: SQ-001's copy, kept identical by SQ-001's parity test.
- `M365-UserQuickCheck/README.md`, `M365-UserQuickCheck/Tests/*.Tests.ps1`.

**Parameters** (match Get-M365SecurityEvidence and AD-UserQuickCheck):
`-UserPrincipalName` (mandatory, position 0, alias `Identity`), `-TenantId`, `-DisableWam`,
`-UseDeviceCode`, `-Days` (`[ValidateRange(1,30)]`, default 7), `-Server` and `-Credential`
(AD stage), `-SkipOnPremises`, `-OutputPath` (optional, as AD-UserQuickCheck), `-TicketNumber`
(SQ-001), `-LoadFunctionsOnly`. Exit codes as AD-UserQuickCheck: 0 can sign in, 1 cannot /
probably not, 2 not found or ambiguous, 3 could not run (module, connect, preflight, wrong tenant).

**Connect and preflight** (copy the pattern from `Get-M365SecurityEvidence.ps1:326-423`):
Microsoft.Graph.Authentication only, `Invoke-MgGraphRequest` for every call, `ContextScope
Process`, `-DisableWam`, `-UseDeviceCode`, preflight `GET /organization` that aborts on a broken
session, `Disconnect-MgGraph` in `finally` (Get-EntraPasswordPolicy.ps1:432-434). Delegated
scopes, read-only: `Directory.Read.All`, `AuditLog.Read.All`,
`UserAuthenticationMethod.Read.All`, `IdentityRiskyUser.Read.All`.

**Gates** (each source reports Available / NotLicensed / NotAllowed / Failed with a reason;
the verdict and the ticket note read the gate, never an empty result):
- Sign-in history: the real `GET /auditLogs/signIns` call is the gate. Classify
  `Authentication_RequestFromNonPremiumTenantOrB2CTenant` as NotLicensed, other 403 as
  NotAllowed, anything else as Failed. `subscribedSkus` service plans (AAD_PREMIUM,
  AAD_PREMIUM_P2) only label the banner; they never override the call's outcome.
- CA detail: Available only if returned rows carry `appliedConditionalAccessPolicies`.
- MFA methods: `GET /users/{id}/authentication/methods`; 403 is NotAllowed.
- Risky user: `GET /identityProtection/riskyUsers/{id}`; P2 licence error is NotLicensed;
  404 means "not flagged" (verify on Learn).
- On-premises AD: module import, then a DC answering.

**Graph stage**: resolve by `userPrincipalName eq`, then fall back to `mail eq` /
`proxyAddresses/any(p:p eq 'smtp:<x>')`; select `id, displayName, userPrincipalName,
accountEnabled, userType, assignedLicenses, licenseAssignmentStates, onPremisesSyncEnabled,
onPremisesLastSyncDateTime, onPremisesProvisioningErrors, onPremisesSecurityIdentifier,
onPremisesSamAccountName, onPremisesDomainName, onPremisesImmutableId, proxyAddresses, mail`.
Sign-ins: `$filter=userId eq '<id>' and createdDateTime ge <now-Days>`, `$top=50`, one page.
Wrong-tenant guard reads `GET /domains` (verified domains) before any user lookup.

**Assessment**: a pure `Get-M365UserAssessment` with the same shape as AD-UserQuickCheck's
`Get-QuickCheckAssessment` (Levels Blocker / Probable / Warning / Info; Reasons with Message and
Action; Passes), plus a `CouldNotCheck` list from the gates. Verdict: any Blocker = NO; any
Probable = PROBABLY NOT; otherwise YES only if sign-in history was Available, else the Q1 label.

**Next-step map** for 50053, 50126, 50057, 50055, 53003, 530035 in the core, each row citing
[reference-error-codes](https://learn.microsoft.com/entra/identity-platform/reference-error-codes)
and labelled "meaning per Microsoft, may change". The text shown as the meaning is always the
log's `failureReason`.

**AD stage** (only when the cloud user is synced, or no cloud user was found; skipped with
`-SkipOnPremises`): runtime `Import-Module ActiveDirectory` in try/catch (no `#Requires
-Modules`). Find the AD account by `onPremisesSecurityIdentifier` (`Get-ADUser -Identity <SID>`),
else by UPN with an RFC 4515-escaped LDAP filter (copy `ConvertTo-LdapFilterValue` from
AD-UserQuickCheck). Read `Enabled, UserPrincipalName, mail, proxyAddresses, pwdLastSet,
DistinguishedName, msDS-cloudExtensionAttribute10`. The block marker name and value come from
`M365-SyncedUserFixes/SyncedUserFixes.Core.ps1:111-112`; cite it. Address conflict lookup: Graph
`users`, `groups`, `contacts` filtered on the AD UPN and primary SMTP. Tenant sync freshness from
`GET /organization` `onPremisesLastSyncDateTime`.

**Must be verified on Microsoft Learn and cited before coding** (root CLAUDE.md; the critic
already verified the signIns licence error, reader roles, CA visibility, risky user P2 and MFA
method roles, see the card):
- `$filter` support on signIns for `userId` and `createdDateTime`; whether v1.0 returns only
  interactive sign-ins; `status.errorCode`, `status.failureReason`, `status.additionalDetails`.
- `proxyAddresses/any()` and `mail` filters on users, groups and orgContacts, and whether they
  need `ConsistencyLevel: eventual` plus `$count=true`.
- `onPremisesProvisioningErrors` fields (`category`, `propertyCausingError`, `value`),
  `onPremisesSecurityIdentifier`, `licenseAssignmentStates.state` values.
- Each delegated scope's least privilege for each call, and that `Directory.Read.All` covers
  `/domains`, `/organization`, `/subscribedSkus`, `/me/memberOf`.
- Entra Connect default sync interval (30 minutes) on the scheduler page.
- The Entra admin center's sign-in log retention for tenants without P1 (used in the non-P1
  next step: "check the user's sign-ins in the Entra admin center"). If Learn does not support
  it, drop that sentence.
- Built-in role template IDs for the roles named in the banner.
- riskyUser 404 behaviour for users never flagged.

**Bundle**: add the folder to the `Build-ServiceDeskToolkit.ps1` manifest (line ~68), a START
HERE row and a "Can't sign in to Microsoft 365" section in `ServiceDesk-Toolkit/README.md`, and
change the existing "Can't sign in" note (line 90-91) to point here. Root `README.md` index row.
`.gitignore`: add `M365-UserQuickCheck/**/M365UserCheck_*` under "Customer data".

## Decisions
### Confirmed by the owner
- D-004 split: this spec covers SQ-002 (Graph stage, AC1-AC17 and AC26-AC29) and SQ-011 (on-prem comparison, AC18-AC25, built after SQ-002).
- D-006 non-P1 headline is PROBABLY YES with "sign-in history not available (no Entra ID P1)".
- D-007 README: consent for yourself only; leave the organization box unticked.
- D-014 runs on the tech workstation or a client server; AD stage says "could not check" when no DC answers.
- D-001: about half of clients have no P1; "no sign-in logs" is a normal path with a useful
  verdict, never a false all-clear (AC8, AC9, AC26).
- D-002: techs often sign in as the client's global admin; the tool stays read-only whatever the
  rights and shows tenant and account first (AC1-AC3).
- D-003: the MSP runs CIPP; no takeover scoring here (that is SQ-007's next step).

### Assumed by the squad
- Folder `M365-UserQuickCheck`, entry `Get-M365UserQuickCheck.ps1`, core `M365UserCheck.Core.ps1`:
  mirrors `AD-UserQuickCheck/Get-ADUserQuickCheck.ps1`, and the folder leaves room for SQ-007.
- PowerShell 5.1 floor for both files: Microsoft.Graph requires 5.1 (root CLAUDE.md; card).
- Microsoft.Graph.Authentication only, all calls via `Invoke-MgGraphRequest`: avoids Graph SDK
  version conflicts (`Get-M365SecurityEvidence.ps1:16`).
- Sign-in gate is the real call's outcome, not the SKU list: P-001; the critic notes licence
  info is not always cached, so SKU and call can disagree.
- Risky user is in v1, gated on P2: the backlog item carries "risky user is P2-only" as a build
  condition. It adds one read scope.
- Verdict levels: blocked and blocking sign-in codes are Blocker (NO); no licence, licence error,
  unmapped latest failure and AD/M365 enabled mismatch are Probable (PROBABLY NOT); no MFA
  method, risky user, stale sync, UPN mismatch are Warning: same scale as AD-UserQuickCheck,
  and none of the warnings stops sign-in on its own.
- Only the most recent sign-in decides the verdict; older failures are Info: an old typo must
  not turn into NO (AC14).
- `-Days` default 7, maximum 30, `$top=50`, one page: enough for a live ticket, and P1 keeps
  30 days.
- Stale sync threshold 3 hours (six missed 30-minute cycles): low noise; verify the 30-minute
  default on Learn.
- AD match by on-premises SID first, then UPN: the SID is exact and does not depend on the
  source anchor choice.
- No password-arrival check (AD `pwdLastSet` versus cloud `lastPasswordChangeDateTime`) in v1:
  whether password hash sync updates the cloud field is not confirmed on Learn, and a wrong
  answer here is the P-001 failure. Listed for stage 3.
- `-OutputPath` optional, console-only without it: same as AD-UserQuickCheck, the sibling
  verdict tool; the SQ-001 note is written separately.
- Exit code 3 for wrong tenant: "could not run", same meaning as AD-UserQuickCheck's 3.
- The banner shows the signed-in account's directory roles (from `/me/memberOf`): helps the
  tech see when they are in as global admin (D-002), and predicts CA visibility.
- Build after SQ-001 is merged: this item consumes `CaseKit.ps1`/`New-TicketNote`; AC26 tests
  the behaviour, not SQ-001's function signature.

## Risk and safety notes
- **personal-data profile applies.** Sign-in rows carry IP addresses, locations and devices.
  Collect only the fields the verdict and the evidence table need (time, app, client app,
  result code, failureReason, CA results, city/country, IP). IPs appear in the local HTML only,
  never in the CSV or the ticket note. HTML-encode every Graph and AD value (AC27). Output stays
  under `-OutputPath`; add the `.gitignore` pattern in the same change. Synthetic fixtures only.
  Least-privilege read scopes, `Disconnect-MgGraph` in `finally`.
- **Client global admin sessions (D-002).** Read-only is enforced three ways: read-only scopes
  only (the token cannot write), GET-only requests, and the static AC3 test. `ContextScope
  Process` keeps the client token out of the tech's persistent cache.
- **Wrong tenant.** Banner first plus the domain guard (AC2). README tells techs to use
  `-DisableWam` when their own work account is picked silently.
- No destructive or system-configuration exposure. Nothing writes to AD or Entra.
- Suggestion for the run report (the squad does not edit config): add `M365-UserQuickCheck/**`
  to the personal-data profile's `paths` in `squad/squad.config.json`.
