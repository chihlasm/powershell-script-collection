# SQ-031 · Smoke-test start mode for RobocopyMigration

- status: ready
- feature: Squad tooling
- size: M
- risk: medium
- touches: `RobocopyMigration/RobocopyMigration-GUI.ps1` (new `-SmokeTest` switch; startup
  code moved below the function definitions; message boxes and change actions routed through
  one wrapper each), `Tests/Invoke-SmokeTest.ps1` (one more default target; refuses a target
  that does not declare `-SmokeTest`), `Tests/Invoke-SmokeTest.Tests.ps1`, new suite
  `RobocopyMigration/Tests/RobocopyMigration-SmokeTest.Tests.ps1`, RobocopyMigration README
  and help

## Summary (plain English)
SQ-029 gave the Folder Permission Manager a "smoke test" start: the real app opens its real
window off-screen, proves it rendered and that its background workers run, closes itself and
prints PASS or FAIL. This item does the same for Robocopy Migration and adds it to the runner,
so the build gate checks that both windows still open after every change. The smoke start asks
for no admin rights, shows nothing on screen, does not look at drives or the network, and does
not read or touch the saved job list or settings (the repo copy's `State\` folder holds real
jobs). It also closes three gaps the SQ-029 review found: every change action is refused at the
point where the change happens, the mode is switched on before any other startup code runs, and
the runner refuses to start a tool that does not have a smoke mode.

## What users will be able to do
- Michael (or the gate, once `smokeCommand` is set) runs
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tests\Invoke-SmokeTest.ps1` and now
  gets two results: the Folder Permission Manager line as today, then
  `[PASS] RobocopyMigration-GUI.ps1: the window opened and closed by itself (...)`, or a `[FAIL]`
  line saying what went wrong. Exit code 0 only if both passed.
- A tech can run `.\RobocopyMigration-GUI.ps1 -SmokeTest` on a server or workstation to check a
  copy of the tool starts there, with no UAC prompt, without disturbing a Robocopy Migration
  window or copy that is already running, and without leaving files behind.
- If someone adds a GUI to the runner's list that has no `-SmokeTest` switch, the runner says so
  and does not start it (instead of starting the tool normally).
- Normal starts of Robocopy Migration are unchanged: relaunch in STA, UAC relaunch, one window
  per tool folder, saved jobs picked up again.

## Approach
**Why the file must be reorganised first.** Today only the pure helpers sit before
`if ($LoadFunctionsOnly) { return }` (line ~903). Everything else (startup checks, themes, XAML,
the background pool, `$script:DriveMap = Get-MappedDriveTable`, every UI function, `Main`) runs
or is defined after it, so tests cannot load or mock any of the window code: Pester 5 can only
mock a command that exists when `Mock` runs. Following the FolderPermissionManager layout
(SQUAD.md "Logic separated from collection and UI"):
- Before the guard: every function, the C# log reader `Add-Type` (as today), and plain data
  (`$script:Themes`, `$script:ResourcesXaml`, `$script:MainXaml`, empty state collections,
  `$script:SettingsPath`, `$script:PresetNames`, `$script:ListFoldersWork`, the smoke helpers).
- After the guard, a `#region Startup` then `#region Main` holding the side effects in today's
  order: startup action (STA, then WPF `Add-Type`, then admin), single-instance lock, background
  pool, drive table, then `Start-MigrationWindow` in the existing try/catch/finally.
- Today's inline startup statements become small functions with the same bodies and texts:
  `Get-StartupAction`, `Request-StaRelaunch` (the `-STA` relaunch), `Request-Elevation` (UAC
  relaunch, with the "needs to run as administrator" box via `Show-RoboMessage`),
  `Enter-SingleInstance` (returns the mutex, or `$null` when another window holds it),
  `Initialize-BackgroundPool`. The settings and job-store reads at the top of
  `Start-MigrationWindow` become `Get-MigrationStartData`; the Closing handler body becomes
  `Invoke-WindowClosing`; the "Open log" click body becomes `Open-JobLog`.
This is a move, not a rewrite: function bodies and user-facing texts stay as they are except for
the smoke checks below.

**Smoke mode (same pattern as SQ-029).**
- `$script:SmokeMode = $SmokeTest.IsPresent` is the first statement after `param()`, before the
  log-reader `Add-Type` (checklist: pre-flag startup paths honour the mode).
- `#region Smoke test` (before the guard): `Add-SmokeFailure` (dedupes, writes the `[FAIL]` line),
  `Test-SmokeRefusal -Action <text>` (in smoke: records "a change was attempted during the smoke
  test: <action>" and returns `$true`), `Get-SmokeVerdict`, `Get-SmokeTickAction`,
  `Set-SmokeWindowMode`, `$script:SmokeProbeWork`, `$script:SmokeDeadline` (30 s),
  `$script:SmokeFailures`, `$script:SmokeState`.
- Startup in smoke: `SmokeNeedsSta` -> `[FAIL]`, `exit 1`; no elevation, no mutex,
  `$script:DriveMap = @{}`; pool and window as normal.
- `Get-MigrationStartData` in smoke returns defaults without touching `State\`;
  `Resume-SavedJobs` returns at once; `Invoke-WindowClosing` skips `Save-All`;
  `Write-GuiError` writes to the console and `Add-SmokeFailure` instead of the file.
- Chokepoints (checklist: enforce at the write layer, not only the UI): the first statement of
  `Start-MigrationJob`, `Stop-MigrationJob`, `Start-RoboPreview`, `Save-JobStore`,
  `Read-JobStore`, `Save-Settings`, `Open-JobDestination`, `Open-JobLog` and
  `Show-BrowseDialog` is `if (Test-SmokeRefusal '<action>') { return }`. Direct UI handlers
  (theme toggle and queue mode -> `Save-Settings`, Clear done -> `Save-All` -> `Save-JobStore`,
  Browse -> `Show-BrowseDialog`) are all covered because they end at one of these.
  `Invoke-NewFolder` runs inside the pool, where `$script:SmokeMode` is not visible, so it is
  covered at its only caller, `Show-BrowseDialog`.
- `Show-RoboMessage -Text -Title -Buttons -Icon` wraps every `[System.Windows.MessageBox]::Show`;
  in smoke it records a failure and returns `'None'`, which every caller treats as "do nothing"
  (`Stop-JobNow` and the Mirror confirm check `-ne 'Yes'`; Closing checks `Cancel`/`No` only).
- `Start-MigrationWindow` in smoke: theme dark, `Set-SmokeWindowMode` after `New-ThemedWindow`
  (off-screen beyond the virtual screen, not in the taskbar, not activated), no `Hide-OwnConsole`;
  `ContentRendered` sets Rendered and starts the probe with `Start-BgTask`; the existing 500 ms
  timer also evaluates `Get-SmokeTickAction` and calls `$win.Close()` on Close/TimedOut.
- Main in smoke: after the finally (pool closed, mutex release is a no-op on `$null`), print the
  verdict lines and `exit` with its code. There is no `Environment.Exit` in this app, and a plain
  `exit` under `-File` carries the code.
- PASS/FAIL texts reuse SQ-029's wording with the script name. None contains "administrator"
  (SQ-029's AC23 asserts the whole runner output has no such word).

**Runner.** Add `'RobocopyMigration\RobocopyMigration-GUI.ps1'` to `$script:DefaultTargets`. Add
`Test-SmokeTargetDeclaresSwitch -Path` (AST; a missing or unparseable file counts as "does not
declare") and call it at the top of `Invoke-SmokeTarget` before `Get-SmokeCommandLine`; a refused
target is Failed (exit 1). Help: `.PARAMETER ScriptPath` says a target without `-SmokeTest` is not
started; `.DESCRIPTION` lists both default GUIs. Stays pure ASCII and 5.1.

**Sibling conflict (SQ-032..SQ-036).** Each of those items adds one line to
`$script:DefaultTargets` and its own tests to `Tests/Invoke-SmokeTest.Tests.ps1`, so all six
conflict on the same lines. This item also changes `Invoke-SmokeTarget` and the SQ-029 count
assertions (AC23), which the siblings should build on rather than repeat. Merge SQ-031 first;
start each sibling from main after the previous one merged (or rebase), and resolve the list as
"keep every line, FPM first, then merge order". Because AC21/AC22 of SQ-029 now count from
`$script:DefaultTargets.Count`, a sibling only adds its list line and its own describe block.

**Docs.** RobocopyMigration README: "Smoke test" section (what it proves, what it does not touch,
the runner command, exit codes), and the "Files the tool creates" section notes that the smoke
test creates none. Help `.NOTES`: "Requires ... Run as administrator" gets "(not for -SmokeTest)".

## Test plan
- Pester 5 under pwsh. New suite `RobocopyMigration/Tests/RobocopyMigration-SmokeTest.Tests.ps1`
  (AC1-AC20); additions to `Tests/Invoke-SmokeTest.Tests.ps1` (AC21-AC23 unit; AC24 helper
  check unit, AC25-AC27 in the existing `Integration`-tagged Describe).
- Backstops in every in-process run: `Start-Process`, `Request-Elevation`, `Request-StaRelaunch`,
  `Enter-SingleInstance`, `Get-MappedDriveTable`, `Get-CimInstance` throw unless the test records
  them; `Start-MigrationWindow` and `Initialize-BackgroundPool` are recording fakes (so no window
  and no pool), `Add-Type` is faked for `-AssemblyName` only (the C# log reader still loads, as in
  the existing suite). Each throwing fake is also asserted `-Times 0 -Exactly`.
- Fakes share data through `$global:` variables removed by name in AfterEach (SQ-029 lesson: in a
  mock body `$script:` is the run's scope). `$script:StateDir`, `JobStorePath`, `SettingsPath`,
  `ErrorLogPath`, `DefaultLogDir` are pointed into `$TestDrive` after every load and every
  in-process run, so no test can reach the repo's real `RobocopyMigration\State\` (which holds
  Michael's real jobs.json).
- `Stop-MigrationJob` calls `taskkill.exe` directly; wrap it in a one-line `Invoke-TaskKill` seam
  so it can be faked (risk profile: native tools are mocked through their wrapper).
- AC16 opens a real runspace pool and runs only the pure probe. AC17 runs only on an STA thread.
- Repo gates: `Tests\Test-ScriptParse.ps1` (5.1 parse; the GUI stays pure ASCII, which the existing
  suite also checks), `Tests\PSVersionFloor.Tests.ps1` (5.1 unchanged), `Tests\ScriptEncoding.Tests.ps1`.
- Edge cases covered: non-STA host, seeded State files with a "Running" job, every chokepoint,
  repeated errors, a message box in smoke, the early-return regression, a target without the
  switch (wrong switch, no param block, unparseable, missing), normal start in all four outcomes.

What the tests cannot see:
- Whether the real Robocopy window renders off-screen and fires `ContentRendered` under Windows
  PowerShell 5.1 on Michael's workstation, and how long a cold start takes (it compiles the C#
  log reader each time). AC25-AC27 cover this but are Integration-tagged; the squad never runs
  them. Once Michael has run them and set `smokeCommand`, the gate's smoke check covers "both apps
  start" on every later item.
- Whether the window ever shows or steals focus on his monitor layout (negative coordinates,
  scaling). Glance once while it runs.
- Whether a normal start still works for real: UAC relaunch, the one-window lock across sessions,
  reattaching to a running copy, and the moved startup code in its real order. The unit tests pin
  the order with fakes; the smoke runs non-elevated and skips those branches. Owner try-list: start
  the tool normally from Explorer, accept UAC, add a small job, close with it running, reopen and
  see it picked up; open a second copy and see the "already open" message.
- Behaviour with no interactive desktop (locked workstation, service session): expected to fail
  with a `[FAIL]` line rather than hang, untested.
- Whether Add-Type's compile leaves anything in TEMP: the real-launch tests redirect TEMP but do
  not assert it is empty.

### Assumed by the squad
- Reorganise the file so all functions are defined before the `-LoadFunctionsOnly` guard.
  Reason: Pester 5 cannot mock a command that does not exist yet, and SQUAD.md requires logic to
  be testable without a window; FolderPermissionManager-GUI.ps1 already has this layout. Not a
  rewrite: bodies and texts move unchanged.
- Smoke does not read `State\` at all (no jobs.json, settings.json, no reattach), not "read but
  don't write". Reason: `Read-JobStore` moves a corrupt file aside and `Resume-SavedJobs` always
  ends with `Save-All`, so reading leads to writing; the repo copy's `State\` holds real jobs
  (gitignored, present on disk); backlog says "no settings ... or directory reads".
- Message boxes, error-log lines and every refused change count as smoke failures; repeated texts
  count once. Reason: SQ-029 decisions and its review (dedupe).
- Chokepoint refusal returns quietly (with a failure) instead of throwing. Reason: a throw would
  reach callers' catch blocks that write to the job object and call `Save-All`; a return changes
  nothing and the failure still fails the run.
- The admin check is skipped in smoke rather than read and ignored. Reason: `Get-StartupAction`
  takes `-IsAdmin` as input; the real `IsInRole` read stays in the startup region and is harmless
  either way. Same outcome as SQ-029.
- Runner refuses targets without a `-SmokeTest` switch, in this item. Reason: SQ-029 review and
  the destructive-operations checklist name it as needed before SQ-031..SQ-036; doing it in the
  first sibling means the others inherit it.
- Updating SQ-029's runner tests to count from the list and to write stub targets (AC23) is
  allowed. Reason: adding a second default target and the declare check makes the literal counts
  and the nonexistent stub paths wrong by design; no assertion is weakened.
- Real-launch tests redirect LOCALAPPDATA, TEMP and TMP for every launch, SQ-029's included.
  Reason: SQ-029 review follow-up and the checklist item.
- Integration time limit for the whole default list is 180 s (two GUIs at up to 90 s each).
  Reason: the runner's per-target timeout stays 90 s.
- Smoke deadline 30 s, runner 90 s per target, exit codes 0/1 (app) and 0/1/2 (runner). Reason:
  same as SQ-029.

## Risk and safety notes
- destructive-operations applies (RobocopyMigration is listed: copies, Mirror deletes, taskkill).
  This item adds no write path; it adds refusals in front of every existing one and must not change
  a normal start (AC20, and the existing suite unchanged).
- SQ-029 checklist gaps, each designed for: enforce at the chokepoint (AC12), pre-flag startup
  paths honour the mode (AC2; the only code before the flag is the param block), runner verifies
  the target declares the mode (AC22), Integration launches redirect LOCALAPPDATA/TEMP (AC24).
- Elevation, prompts and shutdown: the smoke is a "nothing changes" mode and its help lists the
  one startup action that still happens (compiling the log reader). It never relaunches, takes no
  `Global\` mutex (so it cannot lock out or be blocked by a real window), and cannot stop a running
  copy: no jobs are loaded and `Stop-MigrationJob` refuses.
- Tests never touch the repo's real `RobocopyMigration\State\` or `Logs\`: every path is pointed
  into `$TestDrive`, and AC8 uses seeded copies. No unit test launches the GUI or robocopy; agents
  do not run the runner or the Integration tests (SQUAD.md "Real systems", D-062).
- The existing "End to end with real robocopy" tests in `RobocopyMigration-GUI.Tests.ps1` start
  real robocopy and powershell processes on temp folders inside the gate and are not tagged
  Integration. Out of scope here; flagged for Michael as a possible follow-up item.
